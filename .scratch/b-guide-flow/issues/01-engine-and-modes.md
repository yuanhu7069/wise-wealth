# 01: 分账引擎与模式配置（纯函数 + 金例锁定）

**What to build:** 给定一份档案与一个模式，算出各桶每月转入多少、投资桶的大类配置（L2）、以及方案提示（达标／收入不足／短久期不配权益）。四账户与 50/30/20 两种语义都要算对——四账户含固定支出桶、比例桶、规则桶、余量桶与 safety_first 让位链；50/30/20 无余量桶，储蓄桶兼作投资桶。模式库是 TOML 配置，加模式不改代码。

**Blocked by:** None（可立即开工）

**Status:** done（2026-09-10）

**完成记录（2026-09-10）**：46 个测试通过、clippy 零告警、启动期装载已接入。两轮代码审查（标准轴 / 规格轴）后修正：双重取整（缺口 ¥1,199.88 曾被算成 ¥100/月）、规则桶无余量桶时的校验漏网（会超配收入）、`credibility` 与规则名由字符串改枚举、trace 单位改枚举、布尔字段加 `is_` 前缀、消除重复取整与索引重扫。**两处实现期澄清**：①「达标」以 `is_met` + `surplus_cents` 表达，不额外发 Notice（避免同一事实两个来源）；②新增 `build.rs` 扫描模式目录，「加模式 = 加文件不改代码」由承诺变为事实（原先仍要回 `mode.rs` 补一行 `include_str!`）。

**切分理由：** 本 ticket 是唯一一个**非垂直切片**（只有 domain 层 + 单测，没有 API 与 UI）。理由：①它是产品核心，金额算错属产品级事故；②它是规格指定的**主测试接缝**——纯函数、零 IO，可用金例一次覆盖最大风险面；③它不依赖任何其他 ticket，可最早开工、最早退役风险，也能与 02 并行。代价是它本身不可演示，只能以 `cargo test` 验证；若折进 05 会让 05 超出一个上下文窗口。
