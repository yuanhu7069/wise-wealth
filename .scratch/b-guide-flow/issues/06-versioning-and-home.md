# 06: 版本化重算与首页双形态

**What to build:** 收入变了可以重新生成方案——产生新版本，旧版本仍留在库里；重新生成时问卷答案预填上一次的值。首页此时呈现两种形态：还没有方案时引导开始问卷；已有方案时显示摘要（每月可投资多少、应急金状态）并能进入完整方案或直接重新生成。A 期为验证工程骨架而放在首页的 Token 样例区在本 ticket 移除。

**Blocked by:** 05

**Status:** done（2026-09-10）

**完成记录**：后端**未新增端点** —— 版本化本身由 05 落地的 `plans` 两个唯一索引（`plans_user_version_key`、`plans_one_active_per_user`）与事务内「旧版本置非 active → 插入 max+1」保证，本 ticket 只补了一处**冻结列**：迁移 `0005_plan_investable` 给 `plans` 加 `investable_monthly_cents`（生成当时的投资桶月转入，取自引擎的 `l2_bucket_id`），作为首页摘要「每月可投资」的唯一来源 —— 存列而不在读时从桶里挑，是为了不因日后模式配置改动而改写历史方案（与「生成即快照」同一原则）。前端：`page.tsx` 读 `/plans/active` 得三形态（有方案 / 空态 / 局部错误态），新增 `home-view.tsx` 渲染；A 期验证产物从首页移出并删除其死代码（`app/actions.ts`、`components/health-status-card.tsx`、`components/token-samples.tsx`，全文无引用）；`loading.tsx` 骨架改为摘要卡形状；P04「重新生成」补图标与动线注释。

**端到端实测（`.scratch/b-guide-flow/tmp-verify-06.sh`，curl + psql + python 断言，10 节全通过）**：清空方案后首页跑出空态三要素（图标 + 「约 2 分钟」说明 + 「开始问卷」）；金例 A 生成后首页显示「每月可投资 ¥800.00」、模式名与应急金状态句、两个入口；改收入 12,000 → 15,000 重新生成 → **版本 1 → 2**（每月可投资 ¥800.00 → ¥2,500.00），`/plans/active` 指向新版本，库中 `2 行 / 其中 1 行 active`；**数据库层约束**经直接 INSERT 验证：第二条 active 被 `plans_one_active_per_user` 拒绝、重复版本号被 `plans_user_version_key` 拒绝；存款 300,000 后生成第三版，首页切到「应急金已覆盖（约 33.3 个月）」口径。后端 87 项单测全绿（新增「首页摘要的每月可投资取投资桶金额」），`scripts/check.sh` 五道门全绿。

**遗留**：①首页与问卷的**浏览器人工走查**（375px/桌面双端、暗色三态、输入框预填值的肉眼确认）归 ticket 09 验收 —— 脚本只能证明服务端档案完整、问卷落在可重算的步 6 且能回退改数字；②`0005` 之前生成的旧方案行 `investable_monthly_cents` 为 0（迁移用 `DEFAULT 0` 才能让历史行直接升级），首页摘要对这几行显示 ¥0.00，重新生成一次即正确。

**切分理由：** 与 05 拆开的理由见 05。本 ticket 单列还因为它同时约束了两处**数据库层不变量**（单一 active、版本号递增）与首页的信息架构，放在一起验收更内聚。Token 样例区的移除归到这里而非单列 prefactor ticket：它本来就属于「首页改造」这件事，单独拆一张 ticket 只会增加协调成本。
