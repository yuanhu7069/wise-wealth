## 〇、修订说明：这一版改了什么

| 章节 | 相对 V1.0 的变化 | 为什么改 |
| :--- | :--- | :--- |
| 产品定位 | 由单层「模式菜单 + 方案表」改为**双层结构**：起步模式（引导）+ 推演模式（推理，Plus） | V1.0 只服务小白，进阶用户拿到静态表即流失；两个版本各缺一半 |
| 模式库 | 7 个模式拆为 **L1 分账层 / L2 配置层 / L3 执行层**，列表加层级标签 | 原列表把"钱分几堆"和"分完买什么"混排，用户选择时会困惑 |
| 模式出处 | 全面核查，标注 `verified / disputed / caution` 三级可信度 | 初稿 3 处出处有误，详见 §11.2 |
| 生命周期、美林时钟 | 由「可生成方案」降级为**知识库条目** | 杠杆版在国内不可落地；美林时钟 2008 后失效且周期只能事后观测 |
| 模拟引擎 | 由「无」→ V1 三档情景 + 回撤标注 → V2 蒙特卡洛 | 不做预测会被质疑"凭什么信这个比例"；但单条上升曲线是误导，必须给区间 |
| 追踪模块 | 由 5 条功能扩写为独立章节，**逐笔记录改为月度快照** | 追踪是唯一能产生复访理由的模块；逐笔记录是记账类产品的经典死亡陷阱 |
| 成功指标 | 删除不可测指标，改为漏斗式可观测指标 | 「匹配准确率 ≥85%」无 ground truth，无法验收 |
| 账号体系 | Phase 1 免注册，localStorage 起步 | 手机号注册会引入 ICP 备案、短信成本、隐私合规一整套前置成本 |
| 商业化 | 新增，但**仅一章，不做展开** | Plus 分层已确定，需明确边界；但国内理财工具付费意愿低，不宜作为主要收入预期 |

## 一、文档信息

| 项目 | 内容 |
| :--- | :--- |
| 产品名称 | 智策理财（暂定名） |
| 文档版本 | V1.1 |
| 目标用户 | 有理财意愿但缺乏专业知识的个人投资者（起步模式）；希望理解方案成因、自行调整假设的进阶用户（推演模式） |
| 核心定位 | 双层理财决策工具——外层降低起步门槛，内层提供方案推理。**不触碰资金，仅输出建议与模拟** |

### 1.1 产品定位一句话

> **免费层告诉你「怎么做」，Plus 层告诉你「为什么是这个数」以及「换个条件会变成什么」。**

这句话同时是产品边界、商业逻辑和合规底线。

## 二、产品全貌：双层结构

### 2.1 结构总览

```
智策理财
│
├── 起步模式 Guide（免费 · 默认入口）
│   ├── 模式库（L1/L2 分级标签）
│   ├── 引导问卷（4 题，2 分钟）
│   ├── 方案生成 → 一张可照做的表
│   ├── 追踪与反馈（月度快照 → 偏离提醒 → 季度复盘）
│   └── 知识库（模式解读 + 理财百科）
│
├── 推演模式 Lab（Plus · 进阶入口）
│   ├── 推理链展开（这个数字怎么来的）
│   ├── 假设面板（参数可见 / 可调 / 多套保存）
│   ├── 情景推演（三档 + 回撤标注 → V2 蒙特卡洛）
│   ├── 模式对比（2-3 个方案横向叠加）
│   ├── 房贷 vs 投资对比
│   ├── 再平衡模拟器
│   └── 敏感性分析
│
└── 共用内核（一套，不是两套）
    ├── 模式库 YAML（配置驱动，加模式不改代码）
    ├── 规则引擎（L1 分账 → L2 配置 → L3 执行）
    ├── 决策追踪 Decision Trace（推理链的数据来源）
    └── 模拟引擎（情景 / 蒙特卡洛）
```

**关键设计原则：一套内核，两套视图。**
起步模式不是"功能阉割版"，而是"同一份计算结果的不同暴露程度"。这带来三个好处：

1. 引擎只写一次，不会出现两套逻辑给出不同答案的尴尬
2. 免费用户在追踪过程中遇到"为什么会偏离"，可以顺滑地被引导进 Plus
3. 未来若开放 API 或做 B 端，复用的是同一内核

### 2.2 闭合：从"拿到一张表"到"持续用下去"

V1.0 最大的结构性风险是**用完即走**——方案是静态表，用户第二次打开没有理由。V1.1 用下面这个闭环解决：

```
   ① 选模式（问卷推荐 or 自己挑）
        ↓
   ② 出方案（各账户金额 + 各大类比例）
        ↓
   ③ 执行（月度快照：4 个数字，30 秒）
        ↓
   ④ 偏离提醒（月度环比，超阈值温和提示）
        ↓
   ⑤ 季度复盘（坚持月数 / 应急金缺口 / 资产变化）
        ↓
   ⑥ 触发重算（收入变了 / 目标变了 / 人生阶段变了）
        └────────────→ 回到 ②
```

**Plus 层不打断这个闭环，而是叠加在每一环上**：② 可以展开推理链、③ 可以看到偏离对长期结果的影响、⑤ 可以做情景对比、⑥ 可以改假设看变化。

### 2.3 两条用户路径

| | 起步模式（小白 / 月光族 / 家庭管理者） | 推演模式（进阶 / 爱好者 / 专业用户） |
| :--- | :--- | :--- |
| 首次动作 | 4 题问卷 → 得到 1-2 个推荐模式 | 直接进模式库，自己挑或组合 |
| 看到的方案 | 一张金额表 + 每格一句话说明 | 金额表 + 每个数字的推导链条 |
| 关心的问题 | "我这个月该往哪儿放多少钱" | "为什么是 30% 不是 40%？跌 25% 会怎样？" |
| 回访动机 | 月度打卡 + 缺口进度条 | 假设变了 / 想对比新方案 / 市场大跌后看回撤 |
| 转化钩子 | 看到偏离提醒 → "看看影响多大" | — |

## 三、用户分析

### 3.1 目标用户画像

| 画像 | 特征 | 核心需求 | 主用层 |
| :--- | :--- | :--- | :--- |
| **理财小白** | 20-30 岁，刚工作，有储蓄但不知如何管理 | 简单清晰的起步方案，建立理财纪律 | 起步 |
| **月光族** | 收入尚可但存不下钱 | 强制储蓄和分账机制，控制消费 | 起步 |
| **家庭财务管理者** | 30-45 岁，有家庭，需统筹多项目支出 | 系统化的家庭资产配置方案 | 起步 → 推演 |
| **理财爱好者** | 对理财有兴趣，想对比不同策略 | 多模式对比，找到最适合自己的路径 | 推演 |
| **专业/半专业人士** | 懂基础，想验证自己的判断 | 参数可调、假设可换、推理可追溯 | 推演 |

### 3.2 用户故事

| 编号 | 层 | 用户故事 |
| :--- | :--- | :--- |
| US-01 | 起步 | 作为**理财小白**，我希望选择一个简单的理财模式，系统自动告诉我每月工资该怎么分配，这样我就不用自己纠结了。 |
| US-02 | 起步 | 作为**月光族**，我希望系统能帮我建立"先储蓄后消费"的纪律，把钱规划好再让我花。 |
| US-03 | 起步 | 作为**家庭财务管理者**，我希望看到家庭资产的全局配置建议，知道多少钱该花、多少钱该存、多少钱该投资。 |
| US-04 | 起步 | 作为**所有用户**，我希望方案是动态的，当我的收入、年龄或目标变化时，系统能自动更新建议。 |
| US-05 | 起步 | 作为**执行困难户**，我希望每月只花 30 秒记录一次，而不是每笔转账都记账。 |
| US-06 | 推演 | 作为**理财爱好者**，我希望看到"为什么建议我配 30% 权益"，而不是只给我一个数字。 |
| US-07 | 推演 | 作为**风险敏感用户**，我想知道这个方案历史上最惨的时候会跌到多少，我能不能扛住。 |
| US-08 | 推演 | 作为**进阶用户**，我想把"四账户分账"和"杠铃配置"组合起来，看组合后的效果。 |
| US-09 | 推演 | 作为**房贷持有者**，我想比较"提前还贷"和"按方案投资"哪个对我更划算。 |
| US-10 | 推演 | 作为**谨慎用户**，我想改动收益假设，看结论有多敏感——如果改一点点结论就翻转，我就不信这个方案。 |

## 四、起步模式（Guide · 免费）

### 4.1 模式库

#### 4.1.1 分层标签（这是 V1.1 最重要的一处小改动）

模式卡片列表按**两层**分组展示，而不是 7 张平铺卡片。这是零成本的改动，但能解决最大的选择困惑。

- **L1 分账层**：回答"钱进来先切成几堆"——四账户、标准普尔象限、理财金字塔、四笔钱、50/30/20……
- **L2 配置层**：回答"每一堆里装什么大类资产"——杠铃、生命周期、核心-卫星、永久组合……
- **L3 执行层**：回答"怎么买、什么时候调"——定投、再平衡规则……（起步模式不直接暴露，作为方案的一部分自动给出）

> **起步模式的默认路径**：用户只需选 L1（怎么分钱），L2 由问卷答案自动匹配一个默认值，L3 系统给建议。用户看不到 L2/L3 的选择界面，但方案里会写清楚用了什么。
>
> **推演模式才解锁**：L1 × L2 自由组合。

#### 4.1.2 卡片信息

每张卡片包含：模式名称、一句话核心理念、适合人群标签、**出处可信度徽章**。

可信度三级徽章是产品的诚信资产，也是差异化：

| 徽章 | 含义 | 展示方式 |
| :--- | :--- | :--- |
| `verified` 已考证 | 有明确出版物/机构来源 | 绿色徽章，可点开出處详情 |
| `disputed` 存疑 | 广泛流传但出处不成立 | 橙色徽章 + 角标提示 |
| `caution` 谨慎 | 来源真实但个人不可复制 / 有应用边界 | 黄色徽章 + 限制说明 |

#### 4.1.3 对比功能

最多同时对比 **3 个模式**。起步模式下的对比是参数表格；推演模式下升级为**分位数带叠加图**（见 §5.4）。

### 4.2 引导问卷

#### 4.2.1 设计原则：不问"风险偏好"

自评"我能承受高风险"的人，真跌 20% 时该跑还是跑。这个指标与真实行为几乎不相关，初稿中的「风险偏好：保守/稳健/积极」建议**降级为辅助项**。

#### 4.2.2 四个核心问题

| # | 问题 | 为什么问 | 影响哪个参数 |
| :--- | :--- | :--- | :--- |
| Q1 | **这笔钱几年后要用？**（1年内 / 1-3年 / 3-5年 / 5-10年 / 10年以上） | 唯一直接决定"能不能进权益"的变量 | 权益上限 |
| Q2 | **100 万跌到 70 万，你的第一反应是？**（清仓 / 减仓观察 / 不动 / 加仓） | 行为指标，比偏好自评有效一个数量级 | 权益中枢、波动容忍度 |
| Q3 | **收入稳定吗？**（很稳 / 一般 / 波动大 / 自由职业） | 决定应急金留 3 个月还是 12 个月 | 应急金月数 |
| Q4 | **已有保障与负债？**（社保 / 商保 / 房贷余额 / 需赡养人数） | 决定"保命"那堆该多大 | 保障账户比例、负债扣减 |

**年龄**降级为辅助项（生命周期类模式才用）。**家庭人口**并入 Q4。

#### 4.2.3 输出

推荐 **1-2 个 L1 模式 + 1 个匹配的 L2 策略**，并给出一句话推荐理由（该理由即推理链的摘要，见 §5.1）。

### 4.3 方案生成

#### 4.3.1 数据采集字段

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| 月收入 | 数字 | ✅ | 税后月收入 |
| 月固定支出 | 数字 | ✅ | 房租/房贷/车贷等 |
| 现有存款 | 数字 | ❌ | 已有积蓄总额 |
| 年龄 | 数字 | ❌ | 仅生命周期类模式需要 |
| 资金久期 | 单选 | ✅ | Q1 结果 |
| 回撤反应 | 单选 | ✅ | Q2 结果 |
| 收入稳定性 | 单选 | ✅ | Q3 结果 |
| 保障与负债 | 多选+数字 | ❌ | Q4 结果 |
| 理财目标 | 单选 | ✅ | 购房/子女教育/退休/财富增值 |
| 风险偏好 | 单选 | ❌ | 降级为辅助项，仅用于生成参考性描述 |

#### 4.3.2 方案输出结构（以四账户理财法为例）

```
一、分配总览
   ┌ 工资账户    ¥X / 月   用途：大额固定支出扣划
   ├ 消费账户    ¥X / 月   用途：日常饮食、交通、日用品
   ├ 备用账户    ¥X / 月   目标：累计覆盖 6 个月开支（当前 3.2 个月）
   └ 投资账户    ¥X / 月   用途：长期投资

二、投资账户内部配置（L2 自动匹配结果）
   权益类 30% / 债券类 50% / 现金类 20%
   （为什么是这个比例 → Plus 可展开）

三、执行规则（L3 自动给出）
   每月发薪日定投 / 偏离 5% 触发再平衡 / 优先用新增资金补低配

四、落地建议
   建议开 2-3 张银行卡分别对应……（仅建议，不涉及任何划转操作）

五、风险提示（固定展示，见 §10.1）
```

**关键：输出的是比例与金额，绝不出现具体产品名称、代码或链接。** 详见 §9 合规设计。

#### 4.3.3 不同 L1 模式的方案差异

| 模式 | 输出形式 | 核心建议类型 |
| :--- | :--- | :--- |
| 四账户理财法 | 四账户金额分配表 | 收入分流比例 |
| 标准普尔象限 | 四象限金额分配表 | 固定比例（带 `disputed` 标注） |
| 理财金字塔 | 三层资产配置表 | 风险层级配置 |
| 四笔钱 | 四笔钱金额分配表 | 按资金久期分流 |
| 50/30/20 | 三档金额分配表 | 必要/想要/储蓄 |

### 4.4 追踪与反馈（V1.1 重点扩写章节）

这是**唯一能产生复访理由的模块**，也是全产品留存率的决定因素。初稿只写了 5 条，此处扩写。

#### 4.4.1 核心设计变更：月度快照，不是逐笔记录

| | V1.0 方案 | V1.1 方案 | 理由 |
| :--- | :--- | :--- | :--- |
| 记录频率 | 每笔转账手动记录 | **每月一次快照** | 逐笔记录是记账类产品的经典死亡陷阱（随手记、挖财前车之鉴） |
| 填写内容 | 各账户转入金额 | **4 个账户余额**（30 秒完成） | 余额比流水更容易获得，且足够计算偏离 |
| 偏离判断 | 逐笔校验 | **月度环比** | 逐笔校验对用户是负担，对结论无增益 |
| 提醒语 | "偏差超过 20%" | 温和提示 + 一键"本月特殊，跳过" | 生硬的数字提醒会产生负罪感，导致弃用 |

#### 4.4.2 进度可视化的"距离感"设计

进度条展示的不是"完成度百分比"（抽象），而是**具象的距离**：

- ❌ "应急金完成度 53%"
- ✅ "**还差 3.2 个月**攒满应急金" —— 直接对应"我还要坚持多久"
- ✅ "**已坚持 7 个月**" —— 沉没成本转化为继续动力
- ✅ "离首付目标还差 **¥186,000**，按当前速度约 **26 个月**" —— 目标与时间的双重具象

#### 4.4.3 功能清单

| # | 功能 | 说明 |
| :--- | :--- | :--- |
| T1 | 月度快照录入 | 4 个数字，30 秒；支持跳过某月 |
| T2 | 距离感进度条 | 缺口月数 / 已坚持月数 / 目标倒计时 |
| T3 | 偏离提醒 | 月度环比偏离超阈值（默认 20%，可调）时温和提示 |
| T4 | 季度复盘报告 | 坚持月数、各账户变化、缺口收敛速度 |
| T5 | 模式切换 | 人生阶段变化时切换 L1 模式，保留历史快照供对比 |
| T6 | 数据变更触发重算 | 收入/目标/家庭结构变化 → 提示重新生成方案 |
| T7 | 导出 | CSV 导出全部快照（免费） |

#### 4.4.4 Plus 在此环节的叠加

- 偏离提醒旁增加「**看看这个偏离对 10 年后影响多大**」→ 进入情景推演
- 季度报告增加「**按当前轨迹，目标达成概率**」（V2）
- 快照数据用于**真实 vs 计划的对比曲线**

## 五、推演模式（Lab · Plus）

### 5.0 定位

Plus 不是一个独立页面，而是**起步模式每个界面上的「展开」能力**。用户不需要切换模式，而是在看到任何数字时都能往下钻一层。

### 5.1 功能 P1：推理链展开（核心差异化）

**这是 Plus 最重要的一项，也是"方案推理"的字面落地。**

#### 5.1.1 它解决什么

初稿的方案是一张静态表，用户看到"应急金 = 6 个月开支"只能选择信或不信。推理链把黑盒打开：

```
收入稳定性 = "波动大"
   → 匹配规则 emergency_fund_months.branch_unstable
   → 求职周期假设 6-12 个月，取中值 9
   → 月必要开支 ¥8,200 × 9 = ¥73,800
   → 现有存款 ¥24,000
   → 缺口 ¥49,800，按月转入 ¥2,000 需 25 个月
   → 但当前投资账户已分配 ¥1,500/月，存在资源冲突
   → 规则优先级：应急金 > 投资（safety_first）
   → 最终：投资账户暂减至 ¥500/月，直至应急金达标
```

#### 5.1.2 数据结构（引擎侧）

规则引擎每条规则执行时输出 `DecisionTrace`：

```json
{
  "rule_id": "emergency_fund_months",
  "rule_version": "1.2.0",
  "inputs": {"income_stability": "unstable", "dependents": 1},
  "matched_branch": "unstable",
  "branch_condition": "income_stability in ['unstable','freelance']",
  "output": 9,
  "unit": "months",
  "rationale": "收入波动大者需覆盖更长求职周期，取 6-12 个月中值",
  "source": "内部规则（参考 Dave Ramsey Baby Steps 与常规财务规划实践）",
  "conflicts": [
    {"with": "investment_allocation", "resolution": "safety_first", "impact": "投资账户 -1000元/月"}
  ]
}
```

前端渲染为「因为 → 所以」的自然语言链条，**每个节点可点开看规则原文与假设来源**。

#### 5.1.3 借鉴来源

GitHub 上的多智能体金融研究项目（TradingAgents、ai-portfolio-manager）最有价值的不是它们的输出，而是**多角色辩论 + 可追溯推理链**这个工程结构。本产品借鉴的是后者：单引擎、可追溯、每步可解释。

### 5.2 功能 P2：假设面板

#### 5.2.1 诚信底线（免费部分）

**参数可见是免费的，不是 Plus。** 任何涉及收益预测的页面，必须同屏展示所采用的假设值——不可见参数的配置建议，本质上和算命没区别。

免费可见项：各类资产预期收益率、波动率、通胀假设、应急金月数规则。

#### 5.2.2 Plus 部分

| 能力 | 说明 |
| :--- | :--- |
| 参数可调 | 修改 μ / σ / 通胀 / 相关系数 |
| 多套假设保存 | 保存"乐观 / 中性 / 悲观"或个人假设集，一键切换对比 |
| 假设模板 | 提供"保守派 / 主流机构 / 历史平均"三套预设 |
| **默认值警示** | 所有默认参数必须标注「示例参数，请自行校准」 |

> ⚠️ 引擎内的默认参数（如 A 股宽基 μ=7% / σ=20%）**仅作为量级起点，无权威来源**。这一点必须在 UI 上明示，不能藏在文档里。

### 5.3 功能 P3：情景推演

#### 5.3.1 V1：三档情景 + 回撤标注（约 30 行代码）

不做蒙特卡洛，但解决核心问题——**不给单条上升曲线**。

| 档位 | 用途 |
| :--- | :--- |
| 悲观 | 展示"最差也能到哪" |
| 中性 | 展示"按假设会到哪" |
| 乐观 | 展示"顺利的话会到哪" |

**回撤标注（V1.5，约 20 行代码）**：在曲线旁标注"按历史波动，中途最差可能跌到 ¥X"。

> 这一条对起步用户其实比蒙特卡洛更有价值：小白不是怕不涨，是怕跌。告诉他"会跌到多少、你得扛过去"，直接解决"拿不住"这个真实痛点。
>
> **建议：回撤标注考虑下沉到免费层**，作为差异化体验点。

#### 5.3.2 V2：蒙特卡洛 + 目标达成概率

- 参数化 μ / σ / 相关系数矩阵，Cholesky 分解处理相关性
- 10,000 条路径，输出 P10 / P50 / P90 扇形图
- 输出**目标达成概率**（"按此方案，26 个月攒够首付的概率为 68%"），而非"你会有多少钱"
- 支持建模：定期投入、再平衡规则、实际购买力折算
- 性能预算：10k 路径 × 30 年，numpy 向量化后应在 1 秒内完成，可前端 Web Worker 运行

#### 5.3.3 V3（可选）：历史情景压力测试

2008 / 2015 / 2018 / 2022 真实区间回测，以及自定义情景（滞胀、利率下行等）。

### 5.4 功能 P4：模式对比

| 版本 | 形态 |
| :--- | :--- |
| 免费 | 参数表格对比（比例、金额、适用条件） |
| Plus | **分位数带叠加图**——2-3 个方案的 P10-P90 区间叠在同一张图上 |

分位数带叠加是"模式对比"最有力的视觉表达，比参数表格强一个量级：用户能直接看到"A 方案上限更高但下限更低"。

### 5.5 功能 P5：房贷 vs 投资对比（特色功能）

国内家庭最高频的真实决策：**多余的钱是提前还贷还是去投资。**

- 输入：房贷余额、利率、剩余年限、月供、可用资金
- 输出：提前还贷节省的利息（确定性收益）vs 按方案投资的收益分布（含风险）
- 关键呈现：**"提前还贷相当于获得一个 X% 的无风险回报"**——把两个选项放到同一把尺子上

> 这个功能的价值在于：它把一个抽象的配置问题，变成了用户此刻真实面对的二选一。也是免费转 Plus 转化率最可能高的一项。

### 5.6 功能 P6：再平衡模拟器

- 支持规则：日历再平衡 / 阈值再平衡 / 再平衡带 / **现金再平衡**
- 现金再平衡（用新增资金补低配而非卖出）对工薪族最实用：规避赎回费与择时，应作为默认推荐
- 输出：不同再平衡策略下的长期结果差异 + 触发次数（对应操作成本）

### 5.7 功能 P7：敏感性分析

用户改一个参数，看结论变化幅度。若"改一点点结论就翻转"，说明方案对该假设极度敏感——**这个信息本身就是最有价值的输出**。

呈现方式：龙卷风图（tornado chart）或单向敏感性表格。

### 5.8 功能 P8：L1 × L2 自由组合

起步模式自动匹配 L2；Plus 解锁手动组合。

例："四账户分账 + 投资账户内部用杠铃切分" —— 组合后仍输出一张完整表。

### 5.9 功能 P9：数据导出与 API

- CSV / JSON 导出全部方案、快照、推理链
- 只读 API（供用户自建看板 / 第三方接入）

### 5.10 Plus 功能总表

## 六、共用内核设计

### 6.1 模式库 YAML Schema（配置驱动）

加一个模式 = 加一个 YAML 文件，不改代码。这是支撑"覆盖更多模式"目标的地基。

```yaml
id: four_accounts
name: 四账户理财法
layer: L1                      # L1 分账 / L2 配置 / L3 执行
credibility: verified          # verified / disputed / caution
source:
  book: 膨胀吧，钱包君
  author: "[韩] 高敬镐（고경호）"
  original_title: "4개의 통장"
  year: 2011                   # 重庆出版社版；2016 广东人民版名「4个定制账户」
  isbn: 9787218110226
  note: "2011 版名为「四本存折系统」"
tagline: 工资 · 消费 · 备用 · 投资
fit_for: [理财小白, 月光族]
buckets:
  - {id: salary,  name: 工资账户, share: {type: remainder}}
  - {id: spend,   name: 消费账户, share: {type: pct, value: 0.30}}
  - {id: reserve, name: 备用账户, share: {type: rule, rule_id: emergency_fund}}
  - {id: invest,  name: 投资账户, share: {type: remainder}}
rules:
  - rule_id: emergency_fund_months
    branches:
      - {when: "income_stability in [stable]",        value: 3}
      - {when: "income_stability in [normal]",        value: 6}
      - {when: "income_stability in [unstable, freelance]", value: 9}
    rationale: 收入波动大者需覆盖更长求职周期
default_L2: core_satellite
constraints:
  - "备用账户未达标前，投资账户按 safety_first 规则让位"
```

### 6.2 规则引擎执行顺序

```
1. 归一化输入（收入、支出、资产负债、问卷结果）
2. L1 分账：按模式规则切分 → 各桶金额
3. 约束求解：处理桶间资源冲突（优先级：应急金 > 保障 > 投资）
4. L2 配置：对每个投资类桶按策略分配大类资产
5. L3 执行：生成定投/再平衡规则
6. 输出：方案 + DecisionTrace[]（推理链数据来源）
```

**划分原则（一句话）**：涉及"怎么做"的免费，涉及"为什么"和"如果…会怎样"的收费。

### 10.2 定价假设（最不确定的一环，需实测）

- 建议 ¥19.9/月 或 ¥168/年，年付为主
- ⚠️ **现实提醒**：国内理财工具类付费转化率通常 1-3%，Plus 更应被视为**留存机制与用户筛选器**，而非主要收入来源。真正的变现路径更可能是内容引流或 B 端展业工具（后者合规上更稳：工具不直接面对公众，建议由持牌人署名）。
- 本节不做进一步展开，待 MVP 数据出来再定。

## 十二、成功指标（可观测，去掉不可测项）

### 12.1 删除的指标及原因

| 原指标 | 删除原因 |
| :--- | :--- |
| 方案推荐与风险偏好匹配准确率 ≥ 85% | 无 ground truth，无法判定"匹配"与否 |
| 月度回访率 ≥ 40% | 对需手动录入的产品过高，会逼出错误决策；改为跟踪真实值后设定目标 |

### 12.2 新指标体系（漏斗式）

| 阶段 | 指标 | 目标（上线 6 个月） |
| :--- | :--- | :--- |
| 获取 | 注册/首次访问用户数 | ≥ 10,000 |
| 激活 | **问卷完成率**（进入→完成 4 题） | ≥ 70% |
| 激活 | **方案生成率**（完成问卷→生成方案） | ≥ 85% |
| 留存 | **首次快照率**（生成方案→当月记录快照） | ≥ 40% |
| 留存 | **3 个月连续快照率** | ≥ 20% |
| 深度 | Plus 转化率（免费→付费） | ≥ 2% |
| 口碑 | NPS | ≥ 40 |

> 首次快照率是最关键的单一指标——它衡量的是"用户是否真的打算照着做"。建议在 MVP 就埋点。
