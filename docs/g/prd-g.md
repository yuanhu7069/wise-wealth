## 2. 背景与目标

### 2.1 问题陈述

唯一用户（苑问）在 F 期后拥有 4 个 L1 模式与模式库浏览页，但两个缺口仍在：① 模式的「凭什么信」只有一行出处——解读、适用条件、局限性这些可信度依据（产品 PRD §4.5 明言「局限性必须写，这是可信度来源」）没有承载页面，disputed 模式的辟谣也只是一句话而非考据；② 模式之间不可比——想知道「四笔钱和四账户到底差在哪、按我的收入各是多少」时没有工具，只能逐个生成方案再肉眼对照，且每次生成都会切换 active 方案。该问题在每次想换方法或向他人解释产品立场时出现，导致「有出处有可信度的方法集」这一差异化资产停留在标签层面。

### 2.2 目标与价值

- 价值类型：作品完整性（主：Phase 1 收口）+ 自用提效（对比决策）+ 合规立场展示（考据与不可落地专区是产品诚信资产的页面化）
- 目标1：知识库四板块上线，内容可数达标（4+1+8+3），局限性/不建议照搬如实呈现
- 目标2：最多 3 个模式并排对比，金额列按当前档案试算，与单独生成结果对账一致
- 目标3：全程零新依赖、零迁移，内容即配置
- 本期不追求：对比文章、分位数叠加图（Plus P4）、内容后台编辑、百科扩容（§5.2）

### 2.3 成功指标

自用期无外部流量，指标按「达成 / 未达成」判定：

| 指标类型 | 指标名称 | 基线值 | 目标值 | 统计周期 | 如何观测 |
|---------|---------|--------|--------|---------|---------|
| 功能指标 | 知识内容篇数 | 0 | 16（4+1+8+3） | 一次性 | GET /knowledge 计数 |
| 功能指标 | 试算对账一致性 | 无此路径 | 抽 2 模式与单独生成完全一致 | 一次性 | 走查对账 |
| 使用指标 | 对比全链路真实走通 | 无 | ≥1 次（DoD 验收动作） | 一次性 | page_view p08 SQL |

## 4. 用户故事与验收标准

### 4.1 核心用户故事

- US-G-1（读懂方法）：作为唯一用户，我希望在知识库读到每个模式的理论来源、核心逻辑、适用条件与**局限性**，以便知道每个方法「凭什么、边界在哪」。
- US-G-2（看穿存疑）：作为唯一用户，我希望读到标准普尔象限的完整考据，以便向自己（和他人）说清「为什么这个广为流传的方法被标为存疑」。
- US-G-3（知道边界）：作为唯一用户，我希望看到「不可落地」的方法（杠杆版生命周期、美林时钟、耶鲁模式）及其不可落地的原因，以便不被这些名词迷惑。
- US-G-4（对比决策）：作为唯一用户，我希望勾选最多 3 个模式并排对比，金额列按我的档案试算，以便直观看到「同样的钱进来，不同方法切法差多少」。
- US-G-5（术语扫盲）：作为唯一用户，我希望查到再平衡、费率这类术语的一句话解释，以便读懂方案与文章。

### 4.2 验收标准（Given-When-Then）

**知识库内容**

- **AC-1（正常）**：Given 已登录，When 打开 P07，Then 四板块分区呈现：模式解读 4 卡（每卡带所属模式可信度徽章）、考据 1 卡、百科 8 词条卡、不可落地 3 卡（带「仅供理解，不建议照搬」警示徽章），`page_view`（page_id=p07）埋点可查。
- **AC-2（正常）**：Given 打开任一模式解读文章，Then 全文含「理论来源 / 核心逻辑 / 适用条件 / 局限性」四节，局限性一节视觉不弱化；P06 对应卡有「阅读完整解读」链接可达（AC-14）。
- **AC-3（正常）**：Given 打开标准普尔考据，Then 全文可读且与 P06/P04 的存疑徽章、警示条口径一致（从未发布、系国内保险业自创）。
- **AC-4（边界）**：Given 打开不可落地专区任一篇，Then 页面显著标注「仅供理解，不建议照搬」及具体原因，且该模式**不存在于** P06 模式列表与试算（内容与引擎严格分离）。

**模式对比**

- **AC-5（正常）**：Given 在 P06 勾选 2-3 个模式，When 点击「开始对比」，Then 进入 P08，参数表格按维度成行（可信度 / 理念 / 适合人群 / 桶结构 / 必要月支出 / 按你的档案每月转入），勾选态由 URL 参数承载（刷新不丢）。
- **AC-6（正常）**：Given 对比表格含试算金额列，When 与单独生成同一模式的新方案对账，Then 每桶金额完全一致（同档案同引擎，抽样 2 模式）。
- **AC-7（正常）**：Given 勾选含标准普尔象限，When 查看对比表格，Then 其列带存疑徽章；金额照常试算（对比页不做劝阻，诚实呈现原则由徽章与考据链接承载）。
- **AC-8（异常）**：Given 取数或试算失败（网络中断），When 页面发起请求，Then 展示错误态与重试入口，已渲染内容不丢失。
- **AC-9（边界）**：Given 已勾选 3 个模式，When 尝试勾选第 4 个，Then 勾选被拒并提示「最多对比 3 个」。
- **AC-10（边界）**：Given 某模式在当前档案下触发引擎提示（如收入不足），When 查看对比表格，Then 该模式金额列如实显示提示短语而非编造数字。
- **AC-11（边界）**：Given 375px 宽度与 3 列对比，When 查看表格，Then 横向可滑动且首列（维度名）固定，不破版。
- **AC-12（正常）**：Given 直达 URL `/knowledge/<id>`，When 打开，Then 直接呈现该文章全文；未知 id → 404 文案（不白屏）。
- **AC-13（异常）**：Given 会话过期，When 在 P07/P08 取数，Then 内联过期错误 + 重登链接（`from=` 回跳，沿 F 期先例）。
- **AC-14（正常）**：Given 从 P06 点击「阅读完整解读」，Then 到达对应解读文章；返回后 P06 勾选态保持。

**场景覆盖自查**：正常（AC-1/2/3/5/6/7/12/14）、异常（AC-8/13）、边界（AC-4/9/10/11）——三类齐备。

## 6. 业务规则

> 编号承接 F 期 prd-f.md（RULE-032 ～ RULE-037），自 RULE-038 起。

- RULE-038：知识内容是配置——每篇必有唯一 id、kind（`mode_interpretation` | `verification` | `encyclopedia` | `non_implementable`）、标题、至少一个 section（标题 + 段落）；构建期内嵌，加载校验失败即启动失败（同模式库 fail-fast 立场）。
- RULE-039：模式解读类必须关联一个已存在的 L1 模式（related_mode），且**必须包含「局限性」一节**（总 PRD §4.5：局限性必须写，这是可信度来源）；缺失即加载失败。
- RULE-040：不可落地专区每篇必须含「仅供理解，不建议照搬」标注与具体原因；这些条目**不出现在**模式列表、推荐与试算（内容与引擎严格分离）。
- RULE-041：对比一次最多 3 个模式；超出勾选被拒并提示；对比表格为参数表格（可信度 / 理念 / 适合人群 / 桶结构 / 必要月支出 / 试算金额），免费层无图形叠加。
- RULE-042：试算以**当前问卷档案**为基准，对指定模式跑引擎求解——不落库、不产生版本、不改变 active 方案、不影响推荐；档案不完整或不存在的模式 id → 422。
- RULE-043：试算结果如实携带引擎提示；不可行模式（如收入不足）的金额列显示提示短语而非编造数字。
- RULE-044：知识内容合规——全文不出现具体金融产品名称/代码/链接，不承诺收益，不构成投资建议；P07/P08 页脚免责声明沿 RULE-020/031 模式。

自检：以上每条均可回答「是/否」。

### 8.2 核心流程

```
对比路径：
1. P06 勾选 2-3 张卡（超第 4 张被拒并提示）
2. 点「开始对比」→ P08（URL 携带勾选态）
3. 对比表格：维度成行、模式成列；金额列 = 按档案试算
4. 列内可信度徽章 + 存疑列可跳考据（P07）
5. 「返回模式库」→ 勾选态保持

阅读路径：
1. P06 卡「阅读完整解读」→ P07 对应文章
2. 或直达 /knowledge → 四板块 → 选文
3. 文章阅读态：sections 纵排；局限性一节正常排版不弱化

异常路径：
- 取数/试算失败 → 错误条 + 重试
- 会话过期 → 内联过期错误 + 重登链接（from 回跳）
- 未知文章深链 → 404 文案
```

### 9.2 兼容性

Chrome / Edge 最新两个大版本（桌面）；Android Chrome / iOS Safari 现行版本（移动）——与既有六页一致。

### 9.3 可用性与体验

- 无障碍：表格有表头语义（th scope）；375px 横滑表格键盘可达；对比度沿 GitHub 契约
- 内容体验：文章行高放宽；「局限性 / 不建议照搬」不做视觉弱化（诚实呈现）
- 离线能力：无（错误态 + 重试即降级方案）

### 9.4 安全

| 维度 | 要求 |
|------|------|
| 输入校验 | mode_ids 数量 1-3、模式存在性、文章 id 存在性；非法 → 422/404 |
| 越权防护 | 端点全部落入既有 JWT 中间件（白名单零变更） |
| 敏感信息展示 | 知识内容为静态配置文本，无注入面；试算金额仅登录后可见 |
| 凭证管理 | 无新增凭证；`.env` 零新增键 |

### 9.5 埋点与用户行为分析

| 事件名称 | 触发时机 | 关键参数 | 分析目的 | 优先级 | 触发侧 |

金额、试算结果**永不入埋点与日志**（B 期立场继承）。文章阅读为低频行为，不埋单篇事件。

### 9.6 成本与资源上限

无新增外部付费资源。生成期两次 Open Design 调用消耗模型额度（BYOK，单 run ≈5-10 分钟，见 design-g.md §3）。

## 11. 数据合规与隐私

| 维度 | 是否涉及 | 说明 | 处理方式 |
|------|---------|------|---------|
| 个人信息收集 | 否 | 不新增收集（试算读既有档案，不落库） | - |

| 本地存储 | 否 | 无新增 localStorage 键 | - |
| 第三方数据传输 | 否 | 埋点入库不上报（ADR-B-005） | - |
| 数据留存与清理 | 否 | 无新数据表/字段持久化 | - |
| 日志脱敏 | 是 | 试算金额不入日志 | tracing 只带 request_id + 路由名 |
| **内容合规** | **是** | 理财方法论内容面向用户 | RULE-044：不荐产品/不承诺收益/局限性如实；「仅供理解」专区明确标注；免责声明覆盖 P07/P08；引用出版物仅书目信息（合理引用，附 ISBN） |

1. 无硬编码凭证 ✅（零新增配置键）
2. 无明文凭证、日志无敏感原文 ✅
3. 数据隔离与留存：单用户，无新持久化，N/A 已逐项说明 ✅
4. 资金/资产数据：试算只读不落库；金额展示沿既有鉴权与脱敏链 ✅
