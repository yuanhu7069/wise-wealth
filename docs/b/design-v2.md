## 1. 结构层

### 1.1 页面清单（与 prd-v1 §8.1 一一对应）

| 页面 ID | 页面名称 | 所属模块 | 优先级 | 是否需登录 | 说明 |
|---------|---------|---------|--------|-----------|------|
| P01 | 产品首页（改造） | 全局 | P0 | 是 | 双形态；A 期 Token 样例区移除 |
| P02 | 登录页 | 认证 | P0 | 否 | 单表单 + 过期辅助条 |

| P04 | 方案页 | Guide | P0 | 是 | 五段结构静态渲染 |

### 1.2 三条核心路径

1. **首次使用**：`/` → 跳 P02 登录 → P01 空态 →「开始问卷」→ P03 步 1 → …步 6 选模式 → 生成 → P04 五段完整（**8 步内拿到第一个价值**：登录 2 + 空态引导 1 + 问卷 6 + 生成 1，其中问卷 6 步 ≈ 2 分钟，符合产品「4 题 2 分钟」承诺的 B 期形态）
2. **日常主路径**：`/` → P01 摘要卡 →「查看完整方案」→ P04（**2 步内**）
3. **异常路径**：会话过期 → 401 → P02（「登录已过期」辅助条）→ 登录 → 回跳原页（问卷从断点恢复）

### 1.3 导航规则

- 全局导航：**顶部栏**（B 期 4 页且核心路径线性，侧边栏过度）——左「智策理财」品牌（回 P01），右：暗色切换按钮 + 登出按钮（登录后）
- 当前位置：P03 步进条（步 1/6 高亮）；P04/P01 无子层级，靠页面主标题标识
- 返回：P04 →「重新生成」（回 P03 步 6）；P03 →「上一步」逐级 + 顶部「返回首页」；禁止只能靠浏览器返回
- 层级 ≤ 3 层（P01 → P03 → P04）；P02/P03 无子页

### 1.4 响应式策略（design 基线 §9.2「双端并重 = 移动优先 + 桌面增强」）

| 断点 | 布局 |
|------|------|
| < 640px（移动优先基准） | 单列；内容左右边距 --space-lg(16px)；主操作（下一步/生成）**固定底部安全区上方**；步进条压缩为「2/6」数字 + 细进度条 |
| ≥ 1024px | 内容列居中（表单/方案 max-width 720px；P01 摘要 1200px 容器）；主操作随内容流；步进条完整六段 |
| 640-1023px | 同移动单列，边距 --space-xl |

触控：全部可交互元素 ≥ 44×44px（含 A 期 40px Button 修正：移动断点 h-11(44px)）；选项卡整卡可点。

## 2. 原型层（design-v1.html → Token 彩色稿）

产出物：`docs/b/design-v1.html`——单文件可点击原型，走通四页 + 全部异常态。

**保真度：Token 彩色稿（2026-09-10 苑问走查后升级，对 design 基线 §4.3 的显式偏离）**

基线 §4.3 规定原型层用灰阶（「只做结构，不做视觉…不要：渐变、阴影、圆角装饰、动效、彩色」）。本项偏离的理由：

- 灰模的前提是「视觉尚未定稿」；本项目 Token 体系在 A 期已全量落地并验收（`globals.css` + 门禁脚本），前提不成立
- 苑问评审需要判断的是「这个产品长什么样」，纯灰模无法承载该判断
- 升级后本文件**同时充当结构原型与视觉稿**，后续实现直接照此落 Tailwind，一份文件零重复维护
- 记录位置：本节 + §8 基线回填建议（可逆、不意外，故不立 ADR）

实现要点：

- 取值唯一来源 = design 基线 §5（亮色 §5.1.1 / 暗色 §5.1.2 / 字阶 §5.2 / 间距 §5.3 / 圆角 §5.4 / 阴影 §5.5）+ §6.3 图表色板；**文件内无任何规范外自创色值**
- 图标：lucide 线性图标以内联 SVG sprite 引入（`<symbol>` + `<use>`），保持单文件零外部依赖（基线 §4.3「无外部依赖」与 §5.6「统一 lucide 线性图标」同时满足）
- 暗色模式：class 策略（`:root.dark`）+ localStorage 偏好 + 跟随系统默认，主题按钮三态循环——与 §3.3 的实现方案一致，原型即可验收 AC-16
- 真实文案：题目与选项逐字取 prd-v1 §8.2；金例 A 数字进 P04（金额格式与终稿一致：¥4,500.00）
- 状态演示：P01 空态/摘要/骨架切换；P02 凭证错 + 会话过期辅助条；P03 断点恢复（跳步 4）+ 字段校验错误；P04 加载骨架 + 生成失败；调试条「循环状态演示」按钮依次走完 8 态
- 走查要求（基线 §4.2）：四条路径全点通——首次使用 / 日常主路径 / 异常路径（过期→回跳）/ 空数据路径（P01 空态）
- 底部调试条：当前页面 ID + 目标断点 + 当前主题（基线 §4.3 要求）

### 2.1 组件尺寸铁律（本次走查修复的根因，实现期同样适用）

走查发现两类布局缺陷，**同源**——固定尺寸的盒子装可变尺寸的内容：

| 缺陷 | 现象 | 根因 |
|------|------|------|
| 空态图标溢出 | 48px 圆里塞 96px 宽的 `[图标:Compass]` 占位文字，文字撑出圆外压住下一行 | 容器固定宽高 + 长文本占位 |
| 按钮文字折行溢出 | 320px 下「查看完整方案」折成 2 行，88px 行盒塞进 44px 盒子 | `height:44px` + `line-height:44px` 配对装可变文案 |

**规范（写入实现要求）**：

1. 文本容器尺寸由内容撑开：一律 `min-height` + `padding`，**禁止 `height` + `line-height` 配对**装可能换行的文案
2. 图标容器用 `display:grid; place-items:center` + 固定图标尺寸，**禁止用文字当图标占位**
3. 按钮加 `white-space:nowrap`，由**容器**（`flex-wrap:wrap`）负责换行——压缩按钮导致文案折行是缺陷
4. 回归验收：320 / 375 / 768 / 1280 四档宽度跑溢出扫描（`scrollWidth/scrollHeight` vs `clientWidth/clientHeight`），零命中

> 验收记录（2026-09-10）：四档宽度 × 四页面 = 16 组全部零溢出；双主题对比度 6 项全过（正文 10.32:1 / 按钮 5.95:1 等，见 §8）。

### 3.2 文案 → Token 与格式

- 金额：`format-currency.ts` 统一（¥ 千分位 + 2 位小数 + tabular-nums 右对齐）；「约 N 个月」的 N 一位小数
- 问卷题目：--text-section-title；选项文字 --text-body；辅助说明 --text-aux
- 按钮：动词短语（「开始问卷」「下一步」「上一步」「生成方案」「查看完整方案」「重新生成」「登录」「退出登录」）；**一屏一个主按钮**（P03 = 下一步/生成；步 6 双卡下方生成按钮为主，双卡本身是次级选择）

### 3.3 暗色手动切换（补齐 A 期 OUT-008）

- 策略切换为 class 策略：`<html class="dark">` + `@custom-variant dark`；偏好存 localStorage（非敏感，基线 §5.3 允许）；**跟随系统为默认**（无偏好时不加 class，走 media query——与 A 期已实现路径兼容）
- 切换按钮三态循环：跟随系统 → 亮 → 暗 → 跟随系统；aria-label：「切换主题（当前：跟随系统）」
- 值表唯一来源仍是 design 基线 §5.1.2（A 期 globals.css 已全量落地，B 期只加 class 变体接线）

## 5. 动效登记（基线 §8.3，Level B 推荐）

| 动效 | 触发 | 元素 | 时长/缓动 | 取消 | 降级 |
|------|------|------|----------|------|------|
| 步切换 | 下一步成功 | 步内容区淡入 + 步进条填充 | 180ms ease-out | 新步渲染即完 | reduced-motion 直切 |
| 选项卡选中 | 点击选项 | 选中描边 + 勾图标 | 120ms ease-out | - | 直切 |
| 生成跳转 | 生成方案成功 | 页面转场 | ≤300ms ease-out | - | 直切 |
| 骨架 pulse | 取数 >300ms | 骨架屏 | 框架默认 | 响应到达 | 静止（A 期已验） |

同屏同时动效 ≤ 1；全部尊重 `prefers-reduced-motion`（A 期归零块全站生效，B 期复用）。

## 8. 基线回填建议（供 design 基线下一版采纳）

| # | 信号 | 建议 |
|---|------|------|
| 1 | **暗色下「主色填充」对比度不足**：§5.1.2 把暗色 `--color-primary` 提亮为 `#6B8B77`（为文字/描边在深底上够亮），但该值作**填充底色**时白字仅 **3.76:1**，低于 §10 的 4.5:1 底线 | 基线补充一条：「`--color-primary` 的暗色提亮值仅用于文字/描边/图标；**填充型主按钮与实心徽标在暗色下使用 `--color-primary-deep`**（白字 5.95:1）」。或新增 `--color-on-primary` 令牌明确填充态的配字色 |
| 2 | 灰模规范（§4.3）假定「视觉未定稿」；当项目 Token 已定稿时，纯灰模反而阻碍评审 | 基线可补：**「若 design Token 已定稿，原型层可直接产出 Token 彩色稿」**——保留 §4.3 灰阶指令作为「视觉未定稿时」的默认，而非唯一解 |
| 3 | 固定尺寸容器装可变内容的两类翻车（图标占位溢出、按钮 `height`+`line-height` 配对致折行溢出）在 §7.1/§7.2 未明文禁止 | 基线 §7.2 按钮/输入框规范补「尺寸由内容撑开（`min-height`+`padding`）；禁止 `height`+`line-height` 配对」；§5.6 图标补「禁止用文字充当图标占位」 |
