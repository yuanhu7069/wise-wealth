## 2. 背景与目标

### 2.1 问题陈述

苑问（唯一用户）在 A 期结束后拥有一套可运行的工程骨架，但产品价值为零：打开首页只有工程验证页，没有任何「告诉我怎么做」的能力。产品 PRD 的核心承诺（4 题问卷 2 分钟 → 一张可照做的方案表）尚未兑现。
目前的替代解法是凭感觉安排工资分配，导致无法验证「双层理财决策工具」这一产品假设是否成立。
该问题发生频次：每月发薪日；预估代价：产品假设持续无法验证，后续各期（追踪/Plus）全部悬空。

### 2.2 目标与价值

- 价值类型：**自用提效（主）**＋ 作品背书（次）
- 目标1：完成 6 步问卷并生成方案，端到端耗时 ≤ 5 分钟（含阅读）
- 目标2：方案金额与 CONTEXT.md 定稿的分账语义 100% 一致（金例单测锁定）
- 目标3：兑现 A 期三笔承诺——鉴权（ADR-A-001）、业务表 + 备份（ADR-A-002）、埋点链路
- 本期不追求：追踪复访、知识库、Plus 任何能力、对外服务

### 2.3 成功指标

| 指标类型 | 指标名称 | 基线值 | 目标值 | 统计周期 | 如何观测 |
|---------|---------|--------|--------|---------|---------|
| 功能 | 问卷→方案端到端成功率 | - | 苑问走查 100% | 本期 | 手工 ×3 |
| 功能 | 方案生成响应 | - | < 3s（产品 §8.1） | 本期 | 埋点/日志 |
| 体验 | 问卷步保存响应 | - | < 500ms | 本期 | DevTools |
| 体验 | 首屏加载 | - | < 2s | 本期 | DevTools |
| 数据 | 埋点事件入库 | 0 | 5 类事件可 SQL 查验 | 本期 | psql |
| 数据 | 备份恢复演练 | 0 | 1 次成功 | 本期 | 演练记录 |

> 产品 PRD §12.2 漏斗指标（问卷完成率 ≥70% 等）自**对外服务期**起启用并设定目标，自用期只验证链路本身。

### 2.4 目标用户与角色分层

## 3. 用户与权限

### 3.1 用户角色定义

| 角色 | 说明 | 典型操作 | 数据来源 |
|------|------|---------|---------|
| 唯一用户（苑问） | 登录后的完整使用者 | 问卷、生成/查看方案、重新生成 | 种子脚本写入（无注册页） |
| 未登录访客 | 任何未携带会话的访问 | 只能到达登录页；`/health` 可探测 | - |

### 3.2 权限矩阵

| 功能/数据 | 唯一用户 | 未登录 |
|----------|---------|--------|
| P01 首页 / P03 问卷 / P04 方案 | ✅ | ❌（跳登录） |
| P02 登录页 | ✅（已登录则回 P01） | ✅ |
| 模式库 / 档案 / 方案 API | ✅ | ❌（401） |
| GET /health（含 /api/v1/health） | ✅ | ✅ |

### 3.3 登录/注册/鉴权要求

- 是否需要登录：**是**（B 期起全站业务功能需登录；兑现 ADR-A-001）
- 登录方式：用户名 + 密码（单用户，由 `scripts/seed-user.sh` 从环境变量写入；**无注册/找回页**，忘记密码 = 重跑种子脚本重置）
- 会话有效期：30 天（JWT，HttpOnly Cookie）
- 多设备：允许同时登录
- 密码/凭证策略：argon2 哈希存储；登录失败限流（5 次/分钟）

### 3.4 未登录与会话过期处理

| 场景 | 触发条件 | 系统行为 | 用户提示 | 是否保留现场 |
|------|---------|---------|---------|------------|
| 未登录访问受限内容 | 直接访问 P01/P03/P04 | 服务端 302 → `/login?from=<原路径>`（from 仅接受站内路径） | 登录页正常表单 | 是（from 回跳） |
| 会话过期 | JWT 过期后任何业务请求 | 401 → 前端跳 `/login?from=<原路径>` | 登录页辅助文案「登录已过期，请重新登录」 | 是（问卷草稿在服务端，回跳后恢复） |
| 权限不足 | 不适用（单用户无角色分层） | - | - | - |

## 4. 用户故事与验收标准

### 4.1 核心用户故事

- US-01：作为唯一用户，我希望回答 6 步问卷后得到一张可照做的方案表，以便每月发薪日直接执行。
- US-02：作为唯一用户，我希望问卷每步自动保存、中断后从断点继续，以便不因打断而重答。
- US-03：作为唯一用户，我希望重新生成方案时保留历史版本，以便对比收入变化前后的方案。
- US-04：作为唯一用户，我希望登录过期后被送回原页面，以便不丢失正在进行的事。

### 4.2 验收标准（Given-When-Then）

- **AC-1（正常 · 登录）**：Given 种子账号已写入、未登录；When 在 P02 输入正确用户名密码；Then 设置 HttpOnly Cookie，跳转 from 参数指向页（无 from 则 P01）
- **AC-2（异常 · 登录）**：Given 未登录；When 输错密码；Then 表单下方显示「用户名或密码不正确」，不设置 Cookie；连续 5 次失败后第 6 次请求被限流（429 信封），页面提示「操作太频繁，稍后再试」
- **AC-3（异常 · 会话过期）**：Given 问卷已答 3 步、会话过期；When 访问 P03；Then 跳 `/login?from=/questionnaire` 并显示「登录已过期」；重新登录后回到 P03 步 4，已答内容完整
- **AC-4（边界 · from 校验）**：Given 未登录；When 携带 `from=//evil.com` 或 `from=https://evil.com` 访问登录流程；Then from 被丢弃，登录后落在 P01（防开放重定向）
- **AC-5（正常 · 金例生成）**：Given 按金例 A（§7.1）完成 6 步问卷并选择四账户；When 生成方案；Then P04 五段结构与金额与 §7.1 金例 A 表**逐项一致**
- **AC-6（正常 · 草稿恢复）**Given 答完步 3 后关闭页面；When 重新进入 P03；Then 停留在步 4，步 1-3 答案保持选中态
- **AC-7（异常 · 表单校验）**：Given 步 5；When 月收入填 0 / 负数 / 非数字；Then 对应输入框下方出现具体错误文案（如「金额需大于 0」），草稿不落库，步进被阻止
- **AC-8（正常 · 推荐）**：Given 到达步 6；Then 展示四账户与 50/30/20 两张卡片（含可信度徽章与一句话理由），按 RULE-006 标主推；任选其一均可生成方案
- **AC-9（边界 · 短久期）**：Given 久期选「1年内」；When 生成方案；Then L2 配置为现金类 100%，并标注「短期资金不进权益」原因；无权益类比例出现
- **AC-10（边界 · 应急已达标）**：Given 金例 B（存款 ≥ 目标）；When 生成四账户方案；Then 备用账户月转入为 ¥0，该份额落入投资账户，方案展示「应急金已覆盖（约 N 个月）」与「投资账户已有家底 ¥X」（ surplus 仅展示，RULE-013）
- **AC-11（边界 · 收入不足）**：Given 金例 C；When 生成四账户方案；Then 投资桶为 ¥0、备用月转入为 ¥0，方案页展示「收入不足以覆盖当前结构」缺口提示；**任何桶不出现负数金额**
- **AC-12（正常 · 版本化）**Given 已有 active 方案；When 修改收入后重新生成；Then 生成 version+1 新方案并成为 active，旧版本仍存于库中（is_active=false），P01 摘要更新为新方案
- **AC-13（合规红线）**：人工走查 P01-P04 + grep 全部文案与配置；Then 无任何具体金融产品名称、代码、管理机构、购买链接（产品 PRD §9）
- **AC-14（数据 · 埋点）**：完整走一遍流程后；When SQL 查询 analytics_events；Then 5 类事件各至少 1 条（page_view / questionnaire_start / questionnaire_step_completed / questionnaire_completed / plan_generated），plan_generated 载荷含 l1_mode
- **AC-15（数据 · 备份）**：When 执行 scripts/backup.sh 后在副本库恢复；Then 恢复库中方案与档案数据完整可读，演练记录写入 test-report-b.md（兑现 ADR-A-002）
- **AC-16（体验 · 双端与暗色）**：375px 移动视口走通「登录→问卷→方案」无横向滚动、触控目标 ≥44px；P01 呈现「无方案空态 / 有方案摘要」双形态且 Token 样例区已移除；头部暗色手动切换（跟随系统/亮/暗）生效且无残留亮块
- **AC-17（展示 · 金额）**：全站金额千分位 + 2 位小数 + 等宽数字（tabular-nums）右对齐

## 6. 业务规则

> 领域词汇以根 CONTEXT.md 为准（桶/入流/余量桶/规则桶/必要月支出/应急目标/缺口/达标/safety_first/方案）。

- RULE-001：未登录访问任何业务页面/API → 跳登录或 401，携带 from 原路径；**from 只接受以单个 `/` 开头的站内路径**，其余一律丢弃（AC-4）
- RULE-002：登录失败限流：同源 1 分钟内第 6 次失败尝试即拒绝（429），提示「操作太频繁，稍后再试」
- RULE-003：问卷每步「下一步」成功即保存草稿；重新进入恢复到最后已完成的下一步；步内答案保持选中态
- RULE-004：数字字段校验——月收入必填且 > 0；月固定支出 ≥ 0；现有存款 ≥ 0（选填，缺省视为 0）；房贷余额 ≥ 0（选填）；需赡养人数 0-20 整数
- RULE-005：单选步（久期/回撤反应/收入稳定性/理财目标）必答才可进入下一步
- RULE-006：L1 推荐——四账户与 50/30/20 两卡恒同时展示；**现有存款 < 3 × 月固定支出 → 主推四账户**（理由：先建立分账纪律与应急金），否则主推 50/30/20（理由：结构简洁，适合已有储蓄习惯）；用户可选任一
- RULE-007：分账求解顺序——固定支出桶 → 比例桶（基数 = 税后月收入）→ 规则桶 → 余量桶
- RULE-008：一个 L1 模式至多一个余量桶（四账户 = 投资桶）；50/30/20 无余量桶，其储蓄桶（20%）兼作投资桶
- RULE-009：应急月数——收入稳定性映射：很稳 3 / 一般 6 / 波动大 9 / 自由职业 9；**需赡养人数 > 0 上浮一档**（3→6→9→12，上限 12）
- RULE-010：必要月支出 = 模式声明的桶之和（四账户 = 工资桶 + 消费桶；50/30/20 = 必要桶）
- RULE-011：应急目标 = 应急月数 × 必要月支出；缺口 = max(0, 应急目标 − 现有存款)
- RULE-012：规则桶月转入 = 缺口 ÷ 24，**四舍五入到百元**（half away from zero）；缺口 = 0 时转入为 0
- RULE-013：现有存款超过应急目标的部分仅作展示（「投资账户已有家底」），不参与月度分配计算
- RULE-014：safety_first——余量桶 < 0 时：投资桶归零 → 仍不足则缩减规则桶月转入至 0 → 仍不足则方案页展示「收入不足以覆盖当前结构」提示；**任何桶不得出现负数**
- RULE-015：L2 自动匹配——按回撤反应定基础档：清仓/减仓观察 → 永久组合（权益 25%）；不动 → 60/40（权益 60%）；加仓 → 核心-卫星（权益核心 75%，卫星单个 ≤5% 仅文案约束）。久期调整：**1年内 → 覆盖为现金类 100%（不配权益）并标注原因**；1-3年 → 基础档降一档（下限永久组合）；3年以上 → 基础档。收入稳定性不参与 L2
- RULE-016：重新生成方案 = 创建新版本（旧版本保留、is_active 切换，事务保证单一 active）
- RULE-017：全站输出仅到资产大类（权益类/债券类/黄金/现金类），不出现具体产品名称、代码、管理机构、购买链接
- RULE-018：金额全链路整数（分）计算与存储；展示千分位 + 2 位小数 + 等宽数字
- RULE-019：埋点 5 事件（§9.5），上报失败不阻断主流程（静默记录错误日志）
- RULE-020：免责声明**默认只显示一行简述**，其后附「完整声明」链接，点击展开产品 PRD §13.1 原文（展开态在页面切换时自动收起）。**文案与字号**：桌面 = 「本产品提供的所有理财均为基于公开理财理论的参考性建议，不构成任何形式的投资建议」（12px）；**移动端（<640px）= 更短的「理财建议仅供参考，不构成投资建议」@11px**，以保证在 375px 下真正单行不折——11px 低于基线 §5.2 的 12px 下限，属**显式偏离**（2026-09-10 苑问选定，换取操作栏不占过多屏内面积）。**承载位置**：P01/P02 = 站点页脚；**P03 = 向导底部固定操作栏内、按钮下方**（该栏亦不显示站点页脚——否则页脚会被固定栏推到按钮之上，形成「声明在上、按钮在下」的错误堆叠）；P04 = 方案五段之「五、风险提示」，页脚不再重复
  > 取舍说明（2026-09-10 苑问确认）：一行简述牺牲了原文中「不构成…收益承诺或金融产品营销」「模拟推演」「市场有风险」等表述的**常驻**可见性，以换取页脚视觉轻量（成熟站点通行做法）。这些表述仍可通过「完整声明」一步可达。**对外服务期需重新评估**：若产品对外，建议评估是否需将「不构成金融产品营销」一句恢复为常驻（对应 §九 红线）。

### 7.1 核心数据示例（金例，引擎单测与原型共用）

**金例 A（正常 · 四账户）**：月收入 ¥12,000 / 月固定支出 ¥4,500 / 现有存款 ¥24,000 / 久期 5-10年 / 回撤反应 不动 / 收入稳定性 波动大 / 赡养 1 人 / 目标 财富增值

| 桶 | 月转入 | 推导 |
|----|--------|------|
| 工资账户 | ¥4,500 | = 固定支出 |
| 消费账户 | ¥3,600 | = 30% × 12,000 |
| 备用账户 | ¥3,100 | 月数 12（波动大 9 + 赡养上浮一档）；必要月支出 8,100（4,500+3,600）；目标 97,200；缺口 73,200 ÷ 24 = 3,050 → 百元取整 3,100 |
| 投资账户 | ¥800 | 余量 = 12,000 − 4,500 − 3,600 − 3,100 |

展示：应急金当前约 3.0 个月（24,000 ÷ 8,100）；L2 = 60/40（权益 60% / 债券 40%，回撤不动 + 久期 ≥3 年不动档）；约 24 个月补齐缺口。

**金例 C（边界 · 收入不足）**：月收入 ¥8,000 / 固定支出 ¥7,000 / 存款 ¥5,000 / 其余同 A → 消费 2,400、必要 9,400、目标 112,800、缺口 107,800 → 名义转入 4,500，但余量 = 8,000−7,000−2,400−4,500 = **−5,900** → safety_first：投资 ¥0、备用 ¥0，方案页展示「收入不足以覆盖当前结构，请调整收入或支出后重新生成」。

**50/30/20（同金例 A 档案）**：必要 ¥6,000 / 想要 ¥3,600 / 储蓄 ¥2,400；必要月支出 = 必要桶 6,000；目标 72,000；当前 4.0 个月；L3 文案「应急金未达标期间，储蓄桶优先补应急（约 20 个月达标）」；储蓄桶即投资桶（L2 60/40 作用于 ¥2,400）。

### 8.2 核心流程

```

1. 访问 / → 未登录跳 P02 → 登录 → 回 P01
2. P01 空态「开始问卷」→ P03 步 1
3. 步 1-4 单选/多选（久期→回撤反应→收入稳定性→保障与负债）
4. 步 5 财务数字（月收入/月固定支出/现有存款选填/理财目标）

异常路径：
- 会话过期 -> 401 -> /login?from=当前页 -> 登录 -> 回跳（问卷草稿在服务端）
- 表单校验失败 -> 字段下错误文案，阻止步进，草稿不落库
- 生成失败（服务错误）-> P03 步 6 错误态 + 重试，已答数据不丢
- 收入不足 -> 正常生成，P04 展示缺口提示（RULE-014）

问卷 6 步内容（文案唯一来源，产品 PRD §4.2.2 原文）：
步1 这笔钱几年后要用？(1年内/1-3年/3-5年/5-10年/10年以上)
步2 100万跌到70万，你的第一反应是？(清仓/减仓观察/不动/加仓)
步3 收入稳定吗？(很稳/一般/波动大/自由职业)
步4 已有保障与负债？(社保 有/无 · 商保 有/无 · 房贷余额 ¥__ 选填 · 需赡养人数 __)
步5 月收入 ¥__ · 月固定支出 ¥__ · 现有存款 ¥__ 选填 · 理财目标(购房/子女教育/退休/财富增值)

```

## 11. 数据合规与隐私

| 维度 | 是否涉及 | 说明 | 处理方式 |
|------|---------|------|---------|
| 个人信息收集 | 是 | 问卷采集收入/支出/存款/赡养人数等财务画像 | 最小化（仅 §8.2 步 1-5 字段）；仅登录后可见 |
| 账号与认证数据 | 是 | 用户名 + argon2 哈希；JWT 密钥 | 哈希存储；密钥环境变量；Cookie HttpOnly+SameSite=Lax |
| 敏感内容（财务） | **是** | 真实收入/存款数据入库 | 服务端存储；日志脱敏（数值不入日志）；备份加密由实例侧承担 |
| 本地存储 | 是（仅主题偏好） | 暗色切换偏好（system/light/dark） | localStorage 存非敏感偏好（arch 基线 §5.3 允许）；**问卷草稿/方案不在本地存储** |
| 第三方数据传输 | 否 | 无第三方上报 | - |
| 数据留存与清理 | 是 | 方案版本历史永久保留（RULE-016）；埋点事件留存 | 清理策略：版本历史不删；事件表 C 期评估归档 |
| 日志脱敏 | **是** | 请求日志可能接触财务字段 | **必须**：埋点 payload 仅存枚举与步号，不存金额；业务日志禁输出收入/存款数值 |
| 家庭成员共用 | 否 | 单用户 | - |

**红线自查**：①无凭证硬编码（种子凭证经环境变量）；②日志无敏感原文（RULE-019 + §9.4）；③不涉他人数据；④**资金类数据已明确数据准确性校验（金例单测 + 人工核对）与备份策略（backup.sh + 恢复演练，AC-15，兑现 ADR-A-002）**——B 期未演练恢复前不录入不可重建的真实数据。
