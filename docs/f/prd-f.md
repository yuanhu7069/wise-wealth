## 2. 背景与目标

### 2.1 问题陈述

唯一用户（苑问）在 B/E 期后拥有了「问卷 → 方案 → 追踪」闭环，但模式资产几乎不可见：① 引擎只有 2 个 L1 模式（四账户、50/30/20），产品 PRD Phase 1 要求的 5 个缺 3 个，用户每次生成的方案永远只在两种分账法之间二选一；② 没有任何页面能浏览模式——模式的出处、可信度、桶结构这些产品 PRD §4.1 定义的核心展示信息，只存在于配置文件注释里，问卷步 6 的模式选择卡是唯一露出点且无出处；③ 用户想知道「除了推荐的这个，还有什么方法、凭什么信它」时无处可去。该问题每次访问产品都存在，导致「一套内核、多种方法」的产品结构性卖点退化为「单一推荐算法」。

### 2.2 目标与价值

- 价值类型：作品完整性（主：Phase 1 收口 + 诚信资产可见）+ 自用提效（次：多方法可比可选）
- 目标1：4 个 L1 模式全部可出方案（Phase 1 目标 5 个，金字塔挂账；TOML 入库 + 启动校验通过 + 生成成功）
- 目标2：模式库页可浏览、可看出处、可一键用任意模式生成方案
- 目标3：标准普尔的存疑身份在它出现的所有位置有一致的诚实呈现（徽章 + 辟谣）
- 本期不追求：知识库、模式对比、理财金字塔、Plus 全能力（§5.2）

### 2.3 成功指标

自用期无外部流量，指标按「达成 / 未达成」判定，观测走 `analytics_events` SQL：

| 指标类型 | 指标名称 | 基线值 | 目标值 | 统计周期 | 如何观测 |
|---------|---------|--------|--------|---------|---------|

## 4. 用户故事与验收标准

### 4.1 核心用户故事

- US-F-1（浏览）：作为唯一用户，我希望有一页能看到全部 L1 模式的名称、理念、适合人群与可信度，以便知道除推荐之外还有哪些方法。
- US-F-2（出处）：作为唯一用户，我希望展开任一模式看到它的出处与各桶的结构说明，以便判断「凭什么信这个方法」。
- US-F-3（手动生成）：作为唯一用户，我希望在模式库里直接用某个模式生成方案（产生新版本），以便不重走问卷就能换一种分账法试算。
- US-F-4（诚实呈现）：作为唯一用户，我希望存疑模式（标准普尔象限）在出现的一切位置都带存疑徽章与辟谣说明，以便不被广泛流传的说法误导。

### 4.2 验收标准（Given-When-Then）

**模式库浏览**

- **AC-1（正常）**：Given 已登录且模式库含 4 个 L1 模式，When 打开 P06，Then 列表展示 4 张模式卡片，每张含名称 / 一句话理念 / 适合人群标签 / 可信度徽章（文字+颜色）/ 桶概览入口，`page_view`（page_id=p06）埋点可查。
- **AC-2（正常）**：Given 在 P06 展开标准普尔象限卡片，Then 详情含出处（含辟谣说明：标普从未发布，系 2011 年前后国内保险业自创）、四桶概览（10%/20%/30%/40% 与各自用途）与「用此模式生成方案」按钮。
- **AC-3（正常）**：Given 已登录，When 点击 P01 首页「模式库」入口或 P04 方案页「查看全部模式」链接，Then 均一步到达 P06。

**手动生成**

- **AC-4（正常）**：Given 已登录且存在 active 方案（四账户 v1），When 在 P06 对四笔钱点击「用此模式生成方案」并成功，Then 产生新版本方案（v2，active）并跳转 P04，方案页头部显示「四笔钱 · 第 2 版」，`plan_generated` 埋点 entry=mode_lib 可查。
- **AC-5（正常）**：Given 用四笔钱（verified）生成的方案，When 查看 P04，Then 不显示任何可信度提示条，其余呈现与既有方案页一致。
- **AC-6（异常）**：Given 生成过程中网络中断，When CTA 提交失败，Then P06 展示错误提示（卡内错误条 + 内联重试，2026-09-25 走查回填呈现形态），可重试，页面其余状态不受影响。
- **AC-7（异常）**：Given 会话过期后点击 CTA，When 服务端返回 401，Then 卡内显示过期错误与「重新登录」链接（指向 `/login?from=/modes`，登录后回跳 P06）——呈现形态沿 P03 步 6 既有先例（内联错误 + 手动重登，不自动跳转；2026-09-25 走查回填）。

**存疑模式的诚实呈现**

- **AC-8（边界）**：Given 标准普尔象限 credibility=disputed，When 打开问卷步 6 模式选择，Then 该卡显示存疑徽章且**永不**显示「推荐」徽章（推荐规则 RULE-006 不含 disputed 模式）。
- **AC-9（边界）**：Given 用户在 P06 手动对标准普尔象限点击生成并成功，When 查看该方案页，Then 顶部显示警示变体提示条（存疑 + 辟谣一句），方案本身照常可用（金额表 / L2 / 桶明细完整）。
- **AC-10（边界）**：Given 模式可信度为 caution（未来出现），When 查看其方案页，Then 显示提示变体（非警示）条；verified 模式无提示条（映射逻辑单测锁定）。

**页面与安全**

- **AC-11（异常·降级）**：Given 外部 PG 不可达，When 打开 P06，Then 展示错误态与重试入口（沿用 A 期降级链），不出现白屏。
- **AC-12（边界·极端数据）**：Given 模式名 / tagline / 出处文案超长，When 在 375px 宽度查看 P06，Then 文案截断或折行不破版，5 张卡片纵排可用，触控目标 ≥44px。
- **AC-13（边界·防御）**：Given 模式库列表为空（构建期兜底使其实际不可达），When 打开 P06，Then 显示空态防御文案而非白屏。

**场景覆盖自查**：正常（AC-1/2/3/4/5）、异常（AC-6/7/11）、边界（AC-8/9/10/12/13）——三类齐备。

## 6. 业务规则

> 编号承接 E 期 prd-e.md（RULE-021 ～ RULE-031），自 RULE-032 起。

- RULE-032：P06 展示模式库内全部 L1 模式；卡片含名称 / 一句话理念 / 适合人群标签 / 可信度徽章；详情展开展示出处与桶概览（各桶名称 / 用途 / 月转入口径描述）；「推荐」徽章仅出现在推荐规则指向的模式上。
- RULE-033：推荐规则（RULE-006）永不指向 disputed 模式；disputed 模式在其出现的所有位置（P06 卡片 / 详情、问卷步 6）必须带存疑徽章，P06 详情必须含辟谣说明。
- RULE-034：P06 可对任意模式（含 disputed）发起「用此模式生成方案」；生成语义与问卷路径完全一致（同一端点、同一校验），产生新版本方案并置为 active；不设额外交互确认（诚实呈现由徽章 + 辟谣 + 方案页提示条承载）。
- RULE-035：方案页按方案模式的可信度显示提示条——disputed = 警示变体（存疑 + 辟谣一句）、caution = 提示变体（限制说明一句）、verified = 不显示；可信度按**读取时**模式库解析，不随历史方案快照冻结（评级描述模式的知识状态，随配置更新）。
- RULE-036：新增 L1 模式必须是纯配置（TOML），不得为收录新模式修改引擎求解语义（份额类型 / 规则类型 / 求解序）；模式定义与引擎语义冲突时裁剪适配或推后，不得硬塞。
- RULE-037：出处（source）与可信度（credibility）是每个 L1 模式的必备元数据——TOML 必须声明非空 source；加载期校验，缺失或为空则启动失败（fail-fast，同既有坏配置立场）；TOML 注释中的出处信息迁入字段，注释不再承载权威出处。

自检：以上每条均可回答「是/否」。

### 8.2 核心流程

```
正常路径（浏览 → 试算）：
1. P01 首页 →「模式库」→ P06
2. P06 列表浏览卡片（默认收起详情）
3. 展开感兴趣的卡片 → 看出处与桶概览
4. 点「用此模式生成方案」→ 生成中（按钮 loading）
5. 成功 → 跳 P04 方案页（新版本 · active）；（若该模式 disputed）顶部警示条

异常路径：
- CTA 生成失败（网络/服务） → toast → 重试
- 会话过期 → 401 → 登录页（from 回跳 P06）
- 库不可达 → P06 错误态 + 重试（不白屏）
- 问卷路径不变：问卷 → 步 6（含新模式与徽章）→ 生成
```

## 9. 非功能需求（NFR）

### 9.1 性能

| 指标 | 基线（遵循 arch） | 本需求特定要求 | 验收方式 |
|------|-----------------|--------------|---------|
| P06 首屏 | 遵循基线（≤2s dev 局域级） | - | 走查 |
| 模式列表接口 | 遵循基线 | ≤ 200ms（5 项，进程内库遍历） | 走查/网络面板 |
| 手动生成响应 | 遵循基线（与问卷生成同路径） | 无额外开销（同端点） | 复用既有 |
| 详情展开 | - | 无网络请求（数据随列表一次返回） | 实现核对 |

### 9.2 兼容性

Chrome / Edge 最新两个大版本（桌面）；Android Chrome / iOS Safari 现行版本（移动）——与既有五页一致，不额外放宽或收紧。

### 9.3 可用性与体验

- 无障碍：可信度徽章**文字 + 颜色双通道**（「存疑」「已考证」「谨慎」），不只靠颜色区分；键盘可完成浏览 → 展开 → CTA 全流程；焦点可见；对比度沿 GitHub 契约（design-f T1 校验）
- 诚实呈现：存疑不遮蔽——disputed 卡片不因警示而降低可操作性（CTA 照常可用），警示由徽章 + 辟谣 + 方案页提示条三层承载
- 离线能力：无（错误态 + 重试即降级方案）

### 9.4 安全

| 维度 | 要求 |
|------|------|
| 输入校验 | CTA 的模式 id 校验（未知 → 422，既有）；生成入口参数枚举校验（questionnaire / mode_lib） |
| 越权防护 | 接口全部落入既有 JWT 中间件（白名单零变更）；方案查询恒带 user_id |
| 敏感信息展示 | 模式库页无财务数字（桶概览为比例与口径描述）；出处为静态配置文本 |
| 凭证管理 | 无新增凭证；`.env` 零新增键 |

### 9.5 埋点与用户行为分析

| 事件名称 | 触发时机 | 关键参数 | 分析目的 | 优先级 | 触发侧 |
|---------|---------|---------|---------|--------|--------|
| `plan_generated` | 方案生成成功（既有事件） | **新增 `entry=questionnaire\|mode_lib`** | 手动路径使用率（§2.3 核心观测口） | P0 | 服务端 |
| `page_view` | 进入 P06 | page_id=p06（枚举扩） | 模式库触达 | P1 | 客户端（白名单扩） |

金额、余额**永不入埋点与日志**（B 期 §8 立场继承）。模式库浏览为低频行为，卡片展开不做埋点（避免过度采集）。

### 9.6 成本与资源上限

无新增外部付费资源。生成期一次 Open Design 调用消耗模型额度（BYOK，预计单 run ≈5-10 分钟，见 design-f.md §3）。
