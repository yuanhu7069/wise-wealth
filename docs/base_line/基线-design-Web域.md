## 0. 定位与使用方式

### 0.1 边界（与另外两份基线的分工）

| 文档 | 管什么 | 不管什么 |
|------|--------|---------|
| `基线-PRD-Web域.md` | 做什么、为谁做、做到什么算完 | 长什么样、用什么技术 |
| **本文档（design）** | **界面长什么样、交互怎么响应** | 代码结构、技术栈、数据存储、接口设计 |
| `基线-arch-Web域.md` | 用什么技术、怎么组织代码、性能与安全红线 | 视觉与交互细节 |

**三条硬边界**：
1. 本文档**不写技术选型**（框架、组件库、状态管理、构建方式）——那些归 arch；
2. 本文档**不写业务规则**（什么能做什么不能做）——那些归 PRD；
3. 本文档**只做一件事**：让 AI 每次生成出来的界面，看起来像同一个人做的。

### 0.2 苑问的产品调性（3 个关键词）

> **克制 · 高级 · 生活感**

| 关键词 | 意味着 | 反面（禁止） |
|--------|--------|------------|
| **克制** | 色彩少、装饰少、动效轻、信息密度高 | 渐变滥用、大色块、卡片套卡片、彩色图标堆砌 |
| **高级** | 留白足、字阶清晰、对齐严格、细节一致 | 数值随意、间距"肉眼差不多"、圆角大小不一 |
| **生活感** | 暖调中性色、圆角柔和、文案像人说话 | 冷冰冰的企业后台风、技术黑话、机器人腔 |

**一句话总结**：`像一个讲究的人给自己做的工具，不像一个外包团队交付的后台系统。`

### 0.3 规范执行等级（按"给谁用"分级）

OPC 没有"春节大促"这种活动等级，设计投入的分级依据是**这个东西给谁用**：

| 等级 | 适用（对应 PRD §2.2 价值类型） | 必须执行 | 可简化/省略 |
|------|------------------------------|---------|------------|
| **Level A** | **对外服务 / 作品背书**（有外部用户、要拿出去见人） | 全部规范：结构层 → 原型 → 完整 Token → 组件五态 → 动效 → 暗色 | 无 |
| **Level B** | **家庭共用**（家人也要用，用错会来问我） | 结构层 → Token → 组件三态（默认/加载/错误）→ 响应式 | 可省定制插画与复杂动效；暗色可选 |
| **Level C** | **自用提效 / 实验验证**（只有我自己用） | 结构层 → 基础 Token（色/字/间距）→ 关键页面不丑 | 可省原型层、动效、插画；状态只做默认 + 错误 |

**决策原则**：由我在 PRD §12「设计需求声明」中写明等级。
**严禁把 Level C 按 Level A 做（浪费时间），也严禁把 Level A 降级成 Level C（拿不出手）。**

> 疑惑时按**高一级**执行。降级省下的时间，远少于返工与"看着不顺眼"的隐性成本。

## 1. 设计流程门禁（4 层）

```
结构层 → 原型层 → 视觉层 → 验收层
```

| 层级 | 核心问题 | 必交物 | 准出标准 |
|------|---------|--------|---------|
| **1 结构层** | 有哪些页面？怎么流转？ | 页面清单 + 核心路径（§3） | P0 页面全部列出，主路径无断点 |
| **2 原型层** | 布局对不对？流程顺不顺？ | 可点击原型（灰模，见 §4） | 主路径 + 异常路径可点通，**用真实文案** |
| **3 视觉层** | 长什么样？ | 应用 Token 与组件（§5-§9） | 全部数值取自 §5-§6，无发明数值 |
| **4 验收层** | 交互完整吗？ | 验收 Checklist（§12） | 全部通过 |

**层级合并规则**：
- Level A：四层全走，不可合并；
- Level B：可跳过原型层（直接进视觉层）；
- Level C：只走结构层 + 视觉层。

**概念层不在这里**——PRD 的 §2 背景与目标、§2.4 用户分层已经覆盖了（用户问题、目标用户、定位、目标、边界、成功标准）。**不要在设计阶段重复做概念，也不要跳过 PRD 直接做界面。**

## 2. 设计原则（未覆盖场景的推断依据）

本文件没写到的，按这 6 条推断，**禁止自由发挥**：

1. **一致性优先于惊艳**：宁可用规范内的普通方案，不用规范外的惊艳方案。全产品视觉统一 > 单个页面出彩；
2. **数值必须取自本文档**：任何颜色、字号、间距、圆角、阴影、时长，禁止发明新数值；
3. **信息优先于装饰**：能用文字说清的不用图标，能用图标说清的不用插画。装饰元素只在 Level A 出现；
4. **状态必须完整**：任何界面元素都要交代"正常/加载/空/错误/成功"，见 §7.1；
5. **反馈必须即时**：任何操作在 **100ms 内**给出视觉响应（按下态/光标变化即可，不必等结果）；
6. **可恢复优先于防错**：人总会点错。比"阻止他点错"更重要的是"点错了能回来"（撤销、二次确认、软删除）。

## 3. 结构层规范

### 3.1 页面清单模板

所有页面统一编号（P01、P02……），与 PRD §8.1 页面清单**必须一一对应**：

| 页面 ID | 页面名称 | 所属模块 | 优先级 | 是否需登录 | 说明 |
|--------|---------|---------|--------|-----------|------|
| P01 | [如：首页/工作台] | 全局 | P0 | 是 | 默认落地页 |
| P02 | [如：内容详情] | 内容 | P0 | 是 | - |
| P03 | [如：登录] | 全局 | P0 | 否 | - |
| P04 | [如：设置] | 全局 | P1 | 是 | - |

> 新增页面从最大编号顺序递增，并同步更新 PRD §8.1。

### 3.2 三条核心路径（每个应用必填）

1. **首次使用路径**：进入 → 引导/初始化 → 完成第一个核心动作（**必须让人在 3 步内拿到第一个价值**）；
2. **日常主路径**：进入 → 直接到达常用页面 → 完成核心动作（**进入后 2 步内可操作**）；
3. **异常路径**：会话过期 / 网络失败 / 数据为空 → 提示 → 恢复或重试。

### 3.3 导航规则

| 应用类型 | 导航形态 | 规则 |
|---------|---------|------|
| 多页面 Web 应用 | 侧边栏（桌面）/ 底部 Tab（移动） | 一级导航不超过 6 项；当前项必须高亮 |
| 单页面工具 | 无全局导航，页面内按钮流转 | 必须有明确的"返回/完成"出口 |
| Web 套壳桌面 | 侧边栏或顶部菜单 | 遵循所在系统的窗口与菜单习惯 |

规则：
1. **层级不超过 3 层**（列表 → 详情 → 详情内的子页面）；
2. 每个页面必须有回到上一级的入口，**禁止只能靠浏览器返回**；
3. 当前位置必须可见（高亮 / 面包屑 / 标题），**禁止让用户不知道自己在哪**。

## 4. 原型层规范（OPC 版：AI 生成可点击原型）

> 老师版用的是 Figma 低保真。**OPC 没有设计师，也不需要 Figma——直接用 AI 生成 HTML 灰模原型，快得多且能直接演进成真实代码。**

### 4.1 原型的定义

用**真实文案 + 假数据 + 无装饰**的 HTML 页面验证结构与流程：

| 应该覆盖 | 不需要做 |
|---------|---------|
| 所有 P0 页面 | 颜色（用灰阶）|
| 核心路径 + 异常路径 | 图标与插画（用文字标签占位）|
| 空态 / 加载态 / 错误态 | 动效（用箭头或文字标注意图）|
| 导航与返回逻辑 | 真实接口（本地假数据）|
| **真实长度的文案** | 像素级对齐 |

### 4.2 走查要求

四条路径必须全部点通：首次使用 / 日常主路径 / 异常路径 / 空数据路径。

**硬要求**：原型必须用**真实文案**，禁止"文案待定""此处内容"。
**理由**：文案长度直接决定布局。用假文案通过的布局，换成真文案大概率崩——这是 AI 生成界面最常见的返工点。

### 4.3 给 AI 的原型生成指令（可直接复制）

```
请基于 prd-{应用名}.md 的 §8.1 页面清单与 §8.2 核心流程，生成可点击的 HTML 灰模原型：

要求：
1. 单文件 HTML，内联 CSS，无外部依赖（可引 CDN 图标库）；
2. 只做结构，不做视觉：全部使用灰阶（#fff / #f5f5f5 / #e0e0e0 / #999 / #333）；
3. 文案使用 PRD 中的真实文案，禁止"文案待定""Lorem ipsum"；
4. 每个页面必须包含：内容区、空态、加载态、错误态（用注释或切换按钮展示）；
5. 页面间用 <a href="p02.html"> 链接，可真实点击跳转；
6. 底部加一行调试条：显示当前页面 ID 与目标断点。

不要：渐变、阴影、圆角装饰、动效、彩色。
```

## 5. 视觉规范（Token 体系）

### 5.0 Token 使用铁律

1. **所有颜色 / 字号 / 间距 / 圆角 / 阴影 / 时长必须引用本文件定义的 Token，禁止发明数值**；
2. 代码中以 CSS 变量形式落地（`--color-primary` 等），**禁止在组件里写死色值与像素**；
3. 需要新数值时：**先改本文件，再用新 Token**，不许就地发明；
4. 同一语义在不同载体（Web / Web 套壳桌面 / 静态托管）必须映射到同一 Token 名，载体有各自实现方式但 Token 不变。

### 5.1 色彩系统

**主色**：`--color-primary` = **`#4A6B57`（松墨绿）**
> ⚠️ 待确认项：主色是我按"克制·高级·生活感"选定的默认值，非必需。若你想换，只需替换本节的 4 个主色 Token 与暗色映射，全文其余部分无需改动。备选：陶土赭 `#B4643C`（更暖）/ 墨蓝 `#33526B`（更理性）。

**主色使用比例原则**：

| 应用场景 | 主色占比 | 说明 |
|---------|---------|------|
| 页面整体 | 5%-15% | 主色是强调色，不是背景色 |
| 主按钮 | 100% 填充 | 一屏最多一个主按钮 |
| 背景 | 0%-5% | **禁止大面积主色背景** |
| 可点击文字/链接 | 文字色 | 正文中的链接用主色 |

**主色禁忌**：
- 禁止用于错误状态（用 `--color-danger`）；
- 禁止用于辅助文字（用 `--color-text-aux`）；
- 禁止与语义色（success/warning/danger）混用在同一元素上。

4. 暗色下**降低阴影存在感**，改用边框 `--color-divider` 表达层级（见 §5.5）。

### 5.2 字体系统

**字体栈**（不引入外部字体文件，减少加载）：

```css
--font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei",
             "Noto Sans SC", "Segoe UI", Roboto, sans-serif;
--font-mono: "SF Mono", "JetBrains Mono", Consolas, "Courier New", monospace;
```

**字阶固定六档，禁止出现档外字号**：

| Token | 字号 / 字重 / 行高 | 用途 |
|-------|-------------------|------|
| `--text-page-title` | 24px / 600 / 1.35 | 页面主标题（每页最多一个） |
| `--text-section-title` | 18px / 600 / 1.4 | 区块标题、卡片标题、弹窗标题 |
| `--text-body` | 15px / 400 / 1.65 | 正文、列表内容、表格内容 |
| `--text-aux` | 13px / 400 / 1.5 | 辅助说明、时间戳、次要信息 |
| `--text-label` | 12px / 500 / 1.4 | 标签、徽标、状态标记 |
| `--text-data` | 15px / 500 / 1.4 | **数值/金额**（必须用等宽数字，见下） |

**规则**：
1. 正文字号**不得小于 13px**（`--text-aux` 是下限）；
2. **所有数值、金额、日期必须使用 `--text-data` 并开启等宽数字** `font-variant-numeric: tabular-nums`，保证列对齐；
3. 标题**禁止用纯黑 `#000`**，用 `--color-text-title`；
4. 单行文字过长**截断加省略号**，禁止压缩字距（`letter-spacing` 保持默认）。

### 5.3 间距与布局

**4px 基准，只允许取六档**：

| Token | 值 | 用途 |
|-------|------|------|
| `--space-xs` | 4px | 图标与文字之间 |
| `--space-sm` | 8px | 紧凑元素之间 |
| `--space-md` | 12px | 常规元素之间 |
| `--space-lg` | 16px | 模块内分区、卡片内边距（紧凑） |
| `--space-xl` | 20px | 卡片内边距（标准）、页面左右边距（移动） |
| `--space-xxl` | 32px | 模块与模块之间、页面上下留白 |

**布局规则**：
1. **同类元素间距必须一致**，禁止"肉眼差不多"；
2. 页面内容区最大宽度 **1200px**（数据密集页可放宽至 1440px），超出居中；
3. 移动端左右边距 **16px**（`--space-lg`）；桌面端 **32px**（`--space-xxl`）；
4. **留白优先于分割线**：能用间距区分的模块，不加边框。

### 5.4 圆角

| Token | 值 | 用途 |
|-------|------|------|
| `--radius-sm` | 6px | 标签、徽标、输入框 |
| `--radius-md` | 10px | 按钮、下拉项 |
| `--radius-lg` | 14px | 卡片、弹窗、代码块 |
| `--radius-full` | 9999px | 头像、圆形按钮、Pill 标签 |

规则：**同层级元素圆角必须一致**；卡片**禁止内嵌卡片同圆角**（内嵌元素用 `--radius-sm`）。

### 5.5 阴影与层级

阴影**只用三级，且必须轻**（克制原则）：

| Token | CSS 值 | 用途 |
|-------|--------|------|
| `--shadow-card` | `0 1px 3px rgba(31,31,31,0.06)` | 静态卡片，轻微浮起 |
| `--shadow-float` | `0 4px 14px rgba(31,31,31,0.10)` | 下拉、悬浮面板 |
| `--shadow-modal` | `0 12px 40px rgba(31,31,31,0.16)` | 模态弹窗 |

规则：
1. 同一屏**不得出现三级以上阴影**；
2. **禁止给文字加阴影**；
3. 暗色模式下阴影改为 `0 0 0 1px var(--color-divider)`（用边框表达层级）；
4. **能用背景色区分层级就不加阴影**（`--color-bg-page` vs `--color-bg-card` 已足够）。

### 5.6 图标与插画

**图标**：
1. 统一使用**单一图标库**（推荐 Lucide），**禁止混用多套风格**；
2. **图标风格统一为线性（stroke）**，线宽 1.5-2px，**禁止线性与填充混用**；
3. 图标默认尺寸：16px（行内）/ 20px（常规）/ 24px（导航）；
4. 图标默认色 = 所在文字色；语义场景用语义色；
5. **禁止用 emoji 替代功能图标**（不同系统字体下显示不一致）。

**插画**：
1. **Level C 一律不用插画**（用图标 + 文字即可）；
2. Level A/B 仅在**空状态**使用插画，风格统一为**扁平 + 低饱和 + 大圆角**；
3. **禁止**：照片、3D 写实渲染、高饱和卡通、与本产品调性（克制）冲突的任何风格；
4. 格式：图标 SVG；插画 SVG（优先）或 PNG@2x，**单文件 ≤ 50KB**。

## 6. 数据展示规范（苑问特有 · 高优先级）

> **为什么要有这一章**：我的应用大多是数据密集型（理财系统、家庭知识库、生活工作台），而老师的 K12 游戏化规范完全没有这部分。AI 生成表格/图表时最容易出现：数字不对齐、金额无千分位、涨跌色用反、图表配色花哨。**这一章是补 AI 最大短板的。**

### 6.1 表格

| 项 | 规则 |
|----|------|
| 行高 | 默认 44px；紧凑模式 36px（数据量大时） |
| 表头 | 背景 `--color-bg-subtle`，文字 `--color-text-aux`，`--text-label` 字阶，**顶部固定（长表格必填）** |
| 对齐 | **文本左对齐；数值/金额/日期右对齐**；状态列居中 |
| 数字 | 必须用 `--text-data` + `tabular-nums`；**金额必须千分位 + 2 位小数** |
| 分隔 | 仅横向细线 `--color-divider`，**禁止竖线** |
| 斑马纹 | 不用（用 hover 态区分行） |
| Hover | 背景 `--color-bg-subtle` |
| 空态 | 整表空 → 用 §7.3 空状态组件，禁止显示空表头 |
| 超限 | 超过 50 行必须分页或虚拟滚动（**由 arch 基线决定实现方式**） |

### 6.2 数值与涨跌

1. **涨跌配色遵循中国习惯：涨红跌绿**（`--color-up` 红 / `--color-down` 绿），**禁止用反**；
2. 涨跌必须**同时有色 + 符号**（+/- 或 ↑/↓），**禁止只靠颜色传达**（色盲可读）；
3. 数值为 0 或持平 → 用 `--color-text-aux`，不加涨跌色；
4. 金额单位统一（¥ / 元），**全产品一致**；大额可缩写（如 1.2 万），但需 hover 显示精确值。

### 6.3 图表

| 项 | 规则 |
|----|------|
| 配色 | 分类色从**固定色板顺序取**（见下），**禁止随机生成颜色** |
| 色板 | `#4A6B57` `#8AA894` `#C8963E` `#7B8FA1` `#B08070` `#6E7F8D`（低饱和，克制） |
| 数量 | 单图分类**不超过 6 个**，超出归为「其他」 |
| 网格线 | 仅横向，颜色 `--color-divider`，虚线；**禁止纵向网格** |
| 标签 | 直接标注优先于图例；数据标签**不得超过 2 位小数** |
| 动效 | 入场动画 ≤ 400ms；**禁止循环跳动、闪烁** |
| 空/错误 | 图表必须有空态与加载骨架，**禁止渲染空坐标系** |

### 6.4 长文本与内容（家庭知识库类）

1. 正文阅读区**最大宽度 720px**（约 40-45 字/行），超出居中；
2. 正文行高 **≥ 1.75**（`--text-body` 的 1.65 是通用值，正文阅读页可放宽）；
3. 段落间距 = `--space-lg`；标题上下间距 = 上 `--space-xxl` / 下 `--space-lg`；
4. 代码块用 `--color-bg-subtle` + `--radius-lg` + 等宽字体，字号 13px；
5. 长文必须提供**目录/大纲**（层级 ≥ 3 时）。

## 7. 组件规范

### 7.1 状态矩阵（所有可交互组件必须遵守）

**每个可交互组件必须定义五态，缺一态视为未完成**：

| 状态 | 说明 | 视觉规则 |
|------|------|---------|
| **默认** | 常规展示 | 按组件规范 |
| **悬停 / 按下** | 桌面 hover 变色；按下 `transform: scale(0.98)` | 时长 120ms |
| **禁用** | 不可点击 | 透明度 40%，**必须附原因**（Tooltip 或相邻说明），不能只是变灰 |
| **加载** | 处理中 | 按钮内 spinner + 文案变化，**必须禁用防止重复提交** |
| **结果反馈** | 成功 / 失败 | Toast 或状态变化，见 §7.4 |

> **与 PRD §8.3「页面五态」的关系**：PRD 的页面五态（默认/空/加载/错误/成功）是**页面级**，由本节组件状态组合实现。两者不冲突，都要满足。

### 7.2 基础组件

**按钮 Button**

| 类型 | 背景 | 文字 | 圆角 | 高度 |
|------|------|------|------|------|
| 主按钮 | `--color-primary` | `--color-text-inverse` | `--radius-md` | 40px（移动 44px） |
| 次按钮 | `--color-bg-card` + 1px `--color-divider` | `--color-text-body` | `--radius-md` | 40px |
| 危险按钮 | `--color-danger` | `--color-text-inverse` | `--radius-md` | 40px |
| 文字按钮 | 透明 | `--color-primary` | 无 | 32px |

规则：
1. **一屏最多一个主按钮**；
2. 按钮文案为**动词短语**，≤ 6 字：「保存」「添加条目」「生成报表」，**禁止「确定」「好的」**；
3. 主按钮**禁止在页面内重复出现多次**（列表内的操作用文字按钮/图标按钮）。

**输入框 Input**

| 类型 | 高度 | 圆角 | 字号 |
|------|------|------|------|
| 短文本 / 数字 | 40px（移动 44px） | `--radius-sm` | `--text-body` |
| 文本域 | 96px 起，可拉伸 | `--radius-sm` | `--text-body` |
| 选择器/下拉 | 40px | `--radius-sm` | `--text-body` |

规则：
1. **必须带可见标签**，禁止只有占位符（placeholder 不是标签）；
2. 错误态：边框 `--color-danger` + **下方具体错误文案**（如「金额只能是数字，最多 2 位小数」）；
3. 移动端**键盘类型必须匹配输入类型**（数字键盘用于数字）；
4. 必填项用 `*` 标记，禁止用颜色单独表达。

**卡片 Card**

背景 `--color-bg-card`，圆角 `--radius-lg`，内边距 `--space-xl`，可带 `--shadow-card`。
规则：**禁止卡片套卡片**；卡片内的元素用 `--radius-sm`。

**弹窗 Modal**

- 居中 + 遮罩 `--color-bg-overlay`，圆角 `--radius-lg`，`--shadow-modal`；
- **必须有三种关闭方式之一**：右上角 X / 取消按钮 / 点击遮罩（**数据未保存时禁止点遮罩关闭**）；
- **禁止"只能点确定"的弹窗**；
- 底部操作区：次按钮在左，主按钮在右（移动端全宽堆叠，主按钮在上）。

**标签/徽标 Tag**

圆角 `--radius-full`（Pill）或 `--radius-sm`，字阶 `--text-label`，背景用语义色的浅色版（如 `--color-primary-bg`），文字用对应语义色。

**下拉菜单 Dropdown**

`--shadow-float`，圆角 `--radius-md`，项高 36px，hover 背景 `--color-bg-subtle`，当前项用 `--color-primary-bg` + 主色文字。

**Toast 提示**

- 位置：页面顶部居中（桌面）/ 底部（移动）；默认 3 秒自动消失；
- 类型：成功（success）/ 错误（danger，**不自动消失，需手动关闭**）/ 提示（warning）；
- **禁止一屏堆叠多个 Toast**（合并或队列）。

**骨架屏 Skeleton**

- 加载 **> 300ms** 的列表、卡片、图表必须使用骨架屏；
- **禁止只用转圈 spinner**；
- 骨架形状需接近真实内容（不要一整块灰矩形）。

### 7.3 全局状态组件

**空状态 Empty**（**最重要的一个，AI 最常漏**）

三要素缺一不可：
1. 图标或插画（Level C 可用图标）；
2. **一句人话说明**（发生了什么 / 为什么空）；
3. **一个明确的引导操作**。

**禁止只显示"暂无数据"**。示例：
- 内容库：`还没有条目 / 添加第一条，开始积累你的知识库 / [添加条目]`
- 搜索无果：`没找到"XXX" / 换个关键词，或看看筛选条件 / [清除筛选]`

**错误态 Error**

| 错误类型 | 标题 | 说明 | 操作 |
|---------|------|------|------|
| 网络错误 | 网络连接不上 | 检查网络后重试 | [重试] |
| 服务器错误 | 服务出了点问题 | 已记录，稍后再试 | [重试] [返回首页] |
| 权限不足 | 没有访问权限 | 说明为什么 + 谁能给 | [返回] [申请权限] |
| 数据加载失败 | 这部分内容没加载出来 | 其他内容不受影响 | [重试]（局部重试，不刷新整页） |

**文案三要素**（见 §11）：发生了什么 + 为什么 + 怎么办。**禁止技术黑话**。

**加载态 Loading**

| 场景 | 组件 | 文案 |
|------|------|------|
| 页面初始化 | 骨架屏 | 无 |
| 局部刷新 | 骨架屏 / inline spinner | 无 |
| 按钮提交 | 按钮内 spinner + 禁用 | 「保存中…」 |
| 长任务（>3s） | 进度条 + 可取消 | 「处理中 60%」+ [取消] |

### 7.4 组件复用规则

1. **优先使用已有组件，禁止为单一页面新造组件**；
2. 确需新组件时，必须补齐**五态 + Token 引用**后方可使用；
3. **同一功能在全产品只允许一种组件形态**（如"删除确认"只能是一种弹窗样式）；
4. 使用第三方 UI 库时，**必须通过主题覆盖把库默认色映射到本文档 Token**，禁止直接用库默认主题。

## 8. 交互与动效规范

### 8.1 基础参数（克制原则）

| 类型 | 时长 | 缓动 |
|------|------|------|
| 微交互（hover/press/开关） | 120-160ms | `ease-out` |
| 展开/收起、下拉 | 180-250ms | `ease-out` |
| 页面转场 | ≤ 300ms | `ease-out`（入场）/ `ease-in`（退场） |
| Toast 出入 | 200ms / 150ms | `ease-out` |

### 8.2 规则

1. **即时反馈**：任何操作 **100ms 内**必须有视觉响应（按下态即可，不等结果）；
2. **同一屏同时进行的动效不超过 1 个**；
3. **动效只用于表达状态变化与空间关系**，禁止纯装饰动效；
4. **禁止**：自动播放声音、无限循环动画、闪烁频率 > 3Hz 的元素、滚动视差、进入页面即播放的大动画；
5. **必须尊重系统减弱动效设置**（`prefers-reduced-motion: reduce` → 所有动画时长归零，直接切换状态）；
6. 每个动效必须明确四要素：**触发条件 / 触发对象 / 取消条件 / 降级策略**。

### 8.3 动效登记（Level A 必填，Level B 推荐）

| 动效名 | 触发条件 | 元素 | 时长 | 缓动 | 取消条件 | 降级 |
|--------|---------|------|------|------|---------|------|
| [如：卡片展开] | 点击标题 | 卡片高度 | 200ms | ease-out | 再次点击 | 直接展开 |

## 9. 响应式与多端适配

### 9.1 断点

| 名称 | 宽度 | 典型设备 |
|------|------|---------|
| `sm` 移动 | < 640px | 手机竖屏 |
| `md` 平板 | 640 - 1023px | 平板 / 手机横屏 |
| `lg` 桌面 | ≥ 1024px | 笔记本 / 显示器 |

### 9.2 主端优先策略

**在 PRD §1 元信息声明主端，本基线按主端给默认规则**：

| 主端 | 策略 | 关键规则 |
|------|------|---------|
| **移动 Web（手机浏览器）** | 移动优先 | 单列布局；底部 Tab；主操作固定在底部安全区上方；列表无限滚动 |
| **桌面（数据密集：表格/图表/编辑）** | 桌面优先 | 多列布局；侧边导航；表格全量展示；支持键盘操作 |
| **双端并重** | 移动优先 + 桌面增强 | 同一套组件，布局断点切换；**业务规则与数据必须完全一致**（PRD §8.5） |

### 9.3 通用规则

1. **触控热区不小于 44x44px**（成人标准；老师版 60px 是儿童手指标准，我不需要）；热区可大于视觉区域；
2. 移动端**必须处理安全区**（刘海/底部横条）：关键元素距屏幕边缘 ≥ 16px；
3. 不同尺寸下：**文字不截断、按钮不重叠、卡片不溢出、表格可横向滚动**；
4. 桌面端必须支持键盘操作（Tab 焦点、Enter 确认、Esc 关闭弹窗）；
5. **桌面端禁止把移动端的底部 Tab 照搬**（桌面用侧边栏）。

## 10. 可访问性（底线要求）

1. 正文对比度 **≥ 4.5:1**，大标题（≥18px 或 14px 粗体）**≥ 3:1**；
2. **信息不依赖单一颜色传达**（错误必须同时有图标或文案）；
3. 所有可交互元素**可聚焦且焦点态可见**（`:focus-visible` 加 2px 主色描边）；
4. 图片必须有 `alt`；纯装饰图标 `aria-hidden="true"`；
5. 关键操作**不依赖 hover**（移动端没有 hover）；
6. **禁止闪烁频率 > 3Hz** 的动画（光敏性癫痫风险）；
7. 表单错误提示必须与输入框**程序化关联**（`aria-describedby`）。

**常用对比度速查**（本文档色板已满足 WCAG AA）：

| 前景 | 背景 | 对比度 | 可用场景 |
|------|------|--------|---------|
| `#FFFFFF` | `#4A6B57` | 5.4:1 | 主按钮文字 |
| `#1F1F1F` | `#FFFFFF` | 16.9:1 | 卡片正文 |
| `#3D3D3D` | `#FAF9F7` | 11.2:1 | 页面正文 |
| `#8A8580` | `#FFFFFF` | 3.5:1 | **仅可用于辅助文字，不可用于正文** |

### 10.1 可自动验证性要求（2026-09-08 新增）

> **本节只定义「验证什么」，不定义「用什么工具验证」**——工具选型属于 arch 基线 §14.4。
> 这样切分是为了保证：设计规则换技术栈仍成立，验证手段换工具时本文档不用改。

**铁律**：本节与 §5、§7 的每一条规则，都必须**可被机械判定**（能算数值、能查 DOM 属性、能读渲染尺寸）。
**禁止写出无法判定的描述**——"颜色再柔和一点""间距舒服些"这类话对 AI 无效，因为 AI 无法执行、也无法自查。

| 规则 | 判定方式（不提工具） | 通过标准 |
|------|-------------------|---------|
| 正文对比度 ≥ 4.5:1（大字 3:1） | 计算前景/背景实际渲染色的对比度 | 无严重/中等项 |
| 焦点态可见 | 检查 `:focus-visible` 下是否有 outline | 宽度 ≥ 2px |
| 触控热区 ≥ 44x44px | 读取元素实际渲染尺寸 | 宽高均 ≥ 44 |
| 图片有 `alt` / 装饰图标 `aria-hidden` | 检查属性是否存在 | 无严重项 |
| 表单错误与输入框程序化关联 | 检查 `aria-describedby` 指向存在 | 属性齐全 |
| 所有颜色取自 Token | 断言 computed color 落在 Token 集合内 | 全部命中 Token |
| 信息不依赖单一颜色 | 检查错误态是否同时有图标或文案 | 二者至少有其一 |

> **为什么这条重要**：AI 生成界面时最常犯的错，就是给出"看起来对"但无法验证的样式。
> 把规则写成可判定的形式，**AI 才能自查，我才能自动验收**——这是 OPC 无人走查的关键。

## 11. 文案规范（UX Writing）

**语气**：克制、直接、像人说话。**不卖萌、不夸张、不用感叹号堆砌**（区别于 K12 的活泼风）。

| 规则 | 反例 | 正例 |
|------|------|------|
| 按钮用动词 | 确定 / 好的 | 保存 / 添加条目 / 生成报表 |
| 错误三要素 | 操作失败 | 保存失败，网络不太稳。内容已暂存在本地，点重试再存一次 |
| 禁止技术黑话 | 接口超时 / 500 错误 / 空指针 | 服务暂时没响应，稍后再试 |
| 空态要引导 | 暂无数据 | 还没有条目，添加第一条开始积累 |
| 删除要具体 | 确定删除吗？ | 删除「2026年8月账单」？删除后 30 天内可在回收站恢复 |
| 数字格式统一 | 1,000 / 1000 / 1千 | 全产品统一：金额 ¥1,000.00；日期 2026-09-06 |

补充规则：
1. **同一概念全产品用词一致**（如统一叫"条目"不叫"记录/笔记/文档"混用）；
2. 中文界面中数字与单位之间不加空格（除排版需要）；
3. **禁止中英文语气混搭**（如"保存成功！Great!"）；
4. 涉及他人（家人共用）的文案，**不用命令式**（用"你可以…"而非"请…"）。

## 12. 验收 Checklist

### 12.1 结构完整性

- [ ] 页面清单与 PRD §8.1 一致，每页有唯一 ID
- [ ] 三条核心路径（首次/日常/异常）无断点
- [ ] 每个页面有返回上一级入口
- [ ] 导航不超过 3 层，当前位置可见

### 12.2 视觉一致性

- [ ] **所有颜色、字号、间距、圆角、阴影取自 §5 Token，无发明数值**
- [ ] 主色使用比例符合 §5.1，无大面积主色背景
- [ ] 一屏最多一个主按钮
- [ ] 图标风格统一（同一库、线性、统一线宽）
- [ ] 暗色模式（如要求）已定义且对比度达标

### 12.3 交互完整性

- [ ] 所有可交互组件**五态齐全**
- [ ] 空态 / 加载态 / 错误态已设计（**空态三要素齐全**）
- [ ] 长列表/表格有分页或虚拟滚动
- [ ] 触控热区 ≥ 44x44px
- [ ] 动效四要素已标注，且尊重 `prefers-reduced-motion`

### 12.4 数据展示（适用时）

- [ ] 数值右对齐、等宽数字、金额千分位 + 2 位小数
- [ ] **涨跌色为红涨绿跌，且带 +/- 符号**
- [ ] 图表配色取自 §6.3 固定色板，分类 ≤ 6
- [ ] 表格/图表有空态与加载骨架

### 12.5 可访问性与文案

- [ ] 对比度达标（正文 4.5:1 / 大字 3:1）
- [ ] 焦点态可见
- [ ] 无技术黑话，按钮用动词
- [ ] 错误文案包含"发生了什么 + 为什么 + 怎么办"
- [ ] **核心页面自动扫描已通过**（无严重/中等项；手段见 arch §14.4）
- [ ] **§10.1 每条验证点均有对应判定方式**（无"靠感觉"的规则）

## 13. 红线清单（违反即打回）

1. **禁止发明规范外的颜色、字号、间距、圆角、阴影、动效时长数值**；
2. 禁止在组件中**写死色值与像素**（必须走 Token）；
3. 禁止混用多套图标库、禁用线性与填充图标混用；
4. 禁止用 emoji 当功能图标；
5. 禁止一屏多个主按钮；
6. **禁止"暂无数据"式裸空态**（必须有引导操作）；
7. 禁止无反馈操作、无关闭入口的弹窗、不可取消的长任务；
8. **禁止涨跌色用反（必须红涨绿跌）**；
9. **禁止数值不用等宽数字**（列不对齐）；
10. 禁止闪烁频率 > 3Hz 的动画；
11. 禁止技术黑话出现在用户界面；
12. **禁止跳过结构层直接写页面**（这是 AI 最常见的越界）；
13. 禁止卡片套卡片、禁止三级以上阴影。

## 14. AI 生成界面的硬约束（苑问特有 · 本文档最重要的一章）

> **为什么需要**：老师版给设计师看，不需要这一章。我的执行者是 AI，而 AI 写前端有固定的翻车模式。这一章就是**给 AI 的紧箍咒**，也是我审 AI 代码时的 checklist。

**AI 写前端最常犯的 10 个错，逐条对应约束**：

| # | AI 常见的错 | 硬约束 |
|---|------------|--------|
| 1 | 每次生成都发明新色值，页面之间风格漂移 | **必须引用 §5 Token；发现新色值即视为缺陷** |
| 2 | 间距随手写（13px、17px） | **只能用 §5.3 六档间距** |
| 3 | 只做理想状态，没有空态/加载/错误 | **五态齐全（§7.1）+ 空态三要素（§7.3）** |
| 4 | 表格数字左对齐、无千分位、不用等宽数字 | **§6.1 / §6.2 硬规则** |
| 5 | 涨跌色用反（绿涨红跌） | **红涨绿跌，且带符号（§6.2）** |
| 6 | 图表配色随机、花哨 | **必须取 §6.3 固定色板顺序** |
| 7 | 移动端直接缩放桌面布局 | **按 §9 主端策略重排，不是缩放** |
| 8 | 暗色模式只改背景不管文字对比度 | **必须用 §5.1.2 完整映射** |
| 9 | 动效堆砌（每个元素都在动） | **同屏同时动效 ≤ 1，且尊重 reduced-motion（§8）** |
| 10 | 无障碍缺失（div 当按钮、无 focus 态） | **语义标签 + 焦点态可见（§10）** |

### 14.1 给 AI 的界面生成指令（可直接复制）

```
在写任何界面代码之前，先读取并执行 `基线-design-Web域.md`：

1. 所有颜色/字号/间距/圆角/阴影/动效时长，必须引用文档 §5 定义的 Token，
   禁止发明任何新数值。发现文档未覆盖的数值 → 停下来问我，不要自己编。
2. 每个可交互组件必须实现五态：默认 / 悬停按下 / 禁用 / 加载 / 结果反馈。
3. 每个列表、表格、图表必须同时实现：空态、加载骨架、错误态。空态必须包含
   图标 + 说明 + 引导操作三要素。
4. 数值展示：右对齐、等宽数字(tabular-nums)、金额千分位+2位小数。
   涨跌用红涨绿跌，必须带 +/- 符号，不得只靠颜色。
5. 响应式按 §9 主端策略实现，移动端是重排不是缩放。
6. 动效克制：同屏同时进行的动效不超过 1 个，必须支持 prefers-reduced-motion。
7. 使用语义化标签，所有可交互元素焦点态可见。
8. 完成后对照 §12 验收 Checklist 与 §13 红线清单自查，逐项输出 ✅/❌。
```

### 14.2 我的审查动作（AI 交出界面后）

1. **先查数值**：搜硬编码色值（`#` 开头）与奇葩像素（如 `13px`/`17px`）；
2. **再查状态**：把数据清空看空态，断网看错误态，慢速看加载态；
3. **后查数字**：金额是否对齐、千分位、涨跌色；
4. **最后看整体**：两个页面放一起对比，风格是否像同一个人做的。

> 第 1 条最有效且最快——**AI 的规范外数值通常一搜一个准**。

## 15. 工具链与交付（OPC 版）

| 项 | 规范 |
|----|------|
| 设计工具 | **不用 Figma**。原型由 AI 生成 HTML（§4），视觉直接落进代码 |
| Token 载体 | 项目内 `tokens.css`（或 Web 套壳/静态托管的对应实现），**Token 名跨载体一致** |
| 组件载体 | 项目组件目录，每个组件必须有五态 |
| 标注 | 代码中只写 Token 名，禁止写死数值 |
| 版本管理 | Token 变更必须更新本文档版本记录，并同步受影响页面 |

### 15.1 设计变更管理

1. **修改 Token、组件、交互逻辑 → 必须同步更新本文档**并升版本号；
2. 单个页面的局部调整不改基线（记录在 PRD 变更记录）；
3. **基线变更必须回填**：如果某次改动是"文档里没有、但实践中必须这样"，把它写回文档。

### 15.2 设计走查（OPC 版）

Level A 项目上线前必须走查，方式是：

```
我用自己的真实数据 + 真实场景走一遍核心路径（不是看截图），
对照 §12 Checklist 逐项打勾，发现的问题记入项目 TODO。
```

**走查重点顺序**：数值规范 → 状态完整 → 数据展示 → 响应式 → 可访问性。
