## 2. 背景与目标

### 2.1 问题陈述

苑问（唯一开发者）在启动智策理财开发时遇到：仓库目前只有产品 PRD（`docs/智策理财_PRD_V1.1.md`），没有任何工程代码。
目前的替代解法是直接从第一个业务功能开写，导致：基线锁定的技术栈含 4 个较新组合（Rust + axum 0.8、Next.js 16 + React 19、TypeScript 7、Tailwind v4 + shadcn 4），兼容性风险会在业务开发中途才暴露并迫使返工；且每期功能若各自装配，分层、响应信封、Token、类型生成链路会漂移。
该问题发生频次：一次性奠基（此后每期功能都依赖此地基），预估代价：中期返工 2-4 天 ＋ 全期风格与契约不一致。

### 2.2 目标与价值

- 价值类型：**自用提效（主）** ＋ 作品背书（次：为智策理财将来对外服务打底）
- 目标1：全新 clone 后执行 `scripts/start.sh`，**≤ 60 秒**内前后端同时运行且 P01 显示数据库连通（首次冷启动的依赖编译时间另计）
- 目标2：类型生成链路端到端可用：后端 utoipa 注解 → `openapi.json` → `web/src/lib/api-types.ts`，前端引用生成类型编译零报错
- 目标3：design 基线全量 Token 落地为 Tailwind v4 `@theme`，P01 展示样例，前端源码零写死色值
- 本期不追求：任何业务功能（问卷 / 方案 / 快照 / 知识库）、鉴权、部署上线、埋点、CI

### 2.3 成功指标

|---------|---------|--------|--------|---------|---------|

## 4. 用户故事与验收标准

### 4.1 核心用户故事

- **US-01**：作为开发者（苑问），我希望 clone 后一条命令把前后端和数据库连接全部跑起来，以便每次开发不必手工装配环境。
- **US-02**：作为开发者，我希望后端接口类型自动生成到前端，以便接口变更时前端在编译期即报错。
- **US-03**：作为开发者，我希望 P01 首页把 design 基线 Token 全量落地并展示样例，以便后续所有页面引用同一套 Token 不漂移。

### 4.2 验收标准（Given-When-Then）

- **AC-1（正常 · 启动）**
  - Given 全新 clone、`.env` 已按 `.env.example` 填写、外部 PostgreSQL 可达
  - When 执行 `scripts/start.sh`
  - Then ≤ 60 秒内后端在配置端口监听、Next dev server 启动；访问 P01 显示数据库连通状态（`db=ok`）
- **AC-2（异常 · 配置缺失）**
  - Given `.env` 缺失或缺必需键
  - When 执行 `scripts/start.sh` 或后端启动
  - Then 启动立即失败，逐条列出缺失键名，提示复制 `.env.example`；服务不进入运行状态
- **AC-3（异常 · 后端不可达）**
  - Given 后端进程未启动
  - When 打开 P01
  - Then 状态卡片区域显示错误态（ERR-001 文案，含「发生了什么 + 为什么 + 怎么办」），页面其余部分（Token 样例、页脚）正常渲染，提供重试入口——局部失败不整页失败
- **AC-4（正常 · 类型生成）**
  - Given 后端含 utoipa 注解并已运行
  - When 执行 `scripts/gen-types.sh`
  - Then `web/src/lib/api-types.ts` 被生成（含文件头「生成物禁止手改」标注），P01 引用其中的健康响应类型编译通过
- **AC-5（边界 · 类型变更暴露）**
  - Given 后端修改了响应结构且未重新生成类型
  - When 前端 `tsc --noEmit`
  - Then 类型不匹配处立即报错（codegen 价值验证：接口变更前端编译期可见）
- **AC-6（边界 · Token 铁律）**
  - Given P01 渲染完成
  - When 在 `web/src` 下 grep 十六进制色值与任意像素值
  - Then 色值/字号/间距/圆角/阴影仅出现在 `globals.css` 的 `@theme` 定义内，组件源码零写死数值
- **AC-7（边界 · 暗色模式）**
  - Given 系统切换至深色模式
  - When 打开 P01
  - Then 按 design 基线 §5.1.2 暗色映射生效，无纯黑背景与纯白文字，对比度达标
- **AC-8（正常/异常 · 健康信封语义）**
  - Given 后端运行中
  - When 数据库可达时请求 `GET /health`；随后停止数据库再请求
  - Then 两次响应均为 HTTP 200 统一信封；`data.db` 分别为 `"ok"` / `"error"`；响应仅含 `status`、`db`、`version` 三个字段，不含连接串、主机名等内部信息
- **AC-9（边界 · 动效降级）**
  - Given 系统开启 `prefers-reduced-motion: reduce`
  - When 打开 P01 加载态
  - Then 骨架屏静止（无 pulse 动画），功能不受影响

## 6. 业务规则

- RULE-001：`GET /health` 以统一响应信封返回，`data` 仅含 `status`（恒 `"ok"`）、`db`（`"ok"` 或 `"error"`）、`version` 三字段；服务进程存活时 HTTP 恒为 200，数据库可用性由 `db` 字段表达；响应不得包含连接串、主机名、内部路径
- RULE-002：后端启动时校验必需环境变量，缺失即拒绝启动并逐条列出缺失键名；`APP_ENV=dev` 时 `DATABASE_URL_DEV` 必填，`APP_ENV=prod` 时 `DATABASE_URL_PROD` 必填；两键同时配置时必须指向不同数据库（开发库与正式库分离）
- RULE-003：所有后端 HTTP 响应使用统一信封（arch 基线 §6.1）；`errorCode` 只能取自 `error.rs` 中集中定义的 ErrorCode 枚举
- RULE-004：前端所有后端调用必须经 `web/src/lib/api.ts`；后端地址仅存在于服务端环境变量，不得进入浏览器端代码
- RULE-005：`web/src/lib/api-types.ts` 只能由 `scripts/gen-types.sh` 生成，禁止手改
- RULE-006：界面颜色 / 字号 / 间距 / 圆角 / 阴影只取自 `@theme` Token；此类数值仅允许出现在 `globals.css`
- RULE-007：`server/.sqlx/`、`Cargo.lock`、前端 lockfile 必须提交 Git；`.env*`、`target/`、`node_modules/`、`.next/` 必须被 `.gitignore` 排除
- RULE-008：用户可见的错误文案必须包含「发生了什么 + 为什么 + 怎么办」三要素，禁止技术黑话

### 8.2 核心流程

```
正常启动路径：
1. 执行 scripts/start.sh（检查工具链版本 → 检查 .env → 并行启动后端与前端）
2. 后端启动：校验配置 → 建 PgPool → 监听 :8080
3. 前端启动：Next dev 监听 :3000
4. 打开 P01：Server Component 经 lib/api.ts 调 /health
5. 状态卡片显示 db=ok 成功态；Token 样例区常显

页面加载路径：
1. 请求 P01 → Next 返回 loading 骨架（>300ms 时可见）
2. 服务端调 /health → 返回渲染结果

异常路径：
- .env 缺失/缺键 -> 启动失败，列出缺失键（ERR-003）
- 后端未启动 -> P01 状态卡错误态（ERR-001），页面其余部分正常
- 数据库不可达 -> /health 返回 db=error（ERR-002），服务不崩溃
```

## 9. 非功能需求（NFR）

默认遵循 arch 基线 §9，以下为本需求增量：

### 9.1 性能

| 指标 | 基线（遵循 arch） | 本需求特定要求 | 验收方式 |
|------|-----------------|--------------|---------|
| 首屏加载 | < 2s（本地/内网） | P01 dev 首屏 < 2s | DevTools |
| 操作响应 | - | `/health` P95 < 100ms（本地） | curl 计时 |
| 构建产物 | - | 首页 JS < 200KB gzipped | next build 输出 |

### 9.2 兼容性

| 形态 | 需声明的内容 |
|------|-------------|
| WEBAPP | 桌面 Chrome / Edge / Firefox / Safari 最新两个大版本；移动端浏览器 B 期起适配；构建目标为 Next 16 默认现代浏览器目标 |

### 9.3 可用性与体验

- 无障碍：焦点态可见、对比度由 Token 保证（正文 ≥ 4.5:1）
- 数据安全性感知：不适用（无数据操作）
- 离线能力：不适用（本地开发场景）
- 中断恢复：不适用（无表单）

### 9.4 安全

| 维度 | 要求 |
|------|------|
| 输入校验 | A 期无用户输入端点 |
| 越权防护 | A 期无鉴权端点（ADR-A-001）；`/health` 响应字段白名单防内部信息泄露（RULE-001） |
| 敏感信息展示 | `DATABASE_URL_*` 的值禁止出现在日志、响应、错误信息中 |
| 凭证管理 | 全走环境变量；`.env` 不提交；`.env.example` 只含键名 |

### 9.5 埋点与用户行为分析

不适用（A 期无业务行为）。B 期起按智策 PRD §12.2 漏斗指标（问卷完成率、首次快照率等）定义事件。

### 9.6 成本与资源上限

无外部付费资源；PostgreSQL / 缓存中间件为已有资产（外部实例），A 期仅用 PostgreSQL。

## 11. 数据合规与隐私

| 维度 | 是否涉及 | 说明 | 处理方式 |
|------|---------|------|---------|
| 个人信息收集 | 否 | A 期无任何用户输入与采集 | - |
| 账号与认证数据 | 否 | 无账号体系（ADR-A-001） | - |
| 敏感内容（财务/健康/证件等） | 否 | A 期无业务数据；后续金额字段一律 `BIGINT` 分 + `_cents` 后缀（arch 基线 ADR-004），首个资金表落地时强制备份策略（arch-a.md §7） | 架构预留 |
| 本地存储（LocalStorage/Cookie） | 否 | P01 不写任何 localStorage / Cookie；主题偏好等自 B 期起按 arch 基线 §5.3 处理 | - |
| 第三方数据传输 | 否 | 仅依赖包下载（crates.io / npm），无业务数据外传 | - |
| 数据留存与清理 | 否 | 无业务数据留存；代码由 Git 管理 | - |
| 日志脱敏 | **是** | 启动与运行日志可能接触 `DATABASE_URL` | **必须**：配置摘要只输出「已配置/缺失」，禁止输出任何环境变量值（arch 基线红线 2/9） |
| 家庭成员共用 | 否 | 单人使用 | - |

**红线自查**：① 无凭证硬编码（键名在 `.env.example`，值只在服务器端 `.env`）；② 日志无敏感原文（RULE-002 实现时强制）；③ 不涉他人数据；④ 不涉资金数据（备份策略触发时机见 arch-a.md §7 / ADR-A-002）。

## 12. 设计需求声明

- 交互形态：Web 界面（桌面优先，开发验证场景）

- 响应式要求：桌面优先；A 期不要求移动端适配（B 期起）
- 视觉基调：克制 · 高级 · 生活感（design 基线 §0.2）
- 详细设计见 `design-a.md`
