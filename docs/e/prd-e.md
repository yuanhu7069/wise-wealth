## 2. 背景与目标

### 2.1 问题陈述

唯一用户（苑问）在 B 期完成后可以在 2 分钟内生成一张可照做的分账方案，但生成之后没有任何理由再回来：方案是静态表，执行得怎么样、应急金攒到哪了、哪个账户的花销偏离了计划，全部无处记录。目前的替代解法是不追踪（用完即走）或到月底凭记忆估计，导致产品 PRD §2.2 指出的结构性风险成立——「拿到一张表」到「持续用下去」的闭环断在第一环，月度快照这一复访入口缺失。该问题每月发生一次（快照节奏），且随时间推移使产品退化为一次性工具。

### 2.2 目标与价值

- 价值类型：自用提效（主）+ 作品背书（次：复访闭环是产品完整性的证明）
- 目标1：上线当月完成首次真实快照录入（DoD 验收动作）
- 目标2：应急金进度从「P04 一个圆点」升级为具象距离——「还差 X 个月」「已坚持 Y 个月」
- 目标3：单次快照录入（含打开页面）≤ 30 秒
- 本期不追求：知识库、更多 L1 模式、目标倒计时、季度复盘、Plus 全能力（§5.2）

### 2.3 成功指标

自用期无外部流量，指标按「达成 / 未达成」判定，观测走 `analytics_events` SQL：

| 指标类型 | 指标名称 | 基线值 | 目标值 | 统计周期 | 如何观测 |
|---------|---------|--------|--------|---------|---------|
| 功能指标 | 首次真实快照 | 无 | 上线 7 日内 ≥1 条 | 一次性 | `snapshot_submit` SQL |
| 使用指标 | 连续快照月数 | 0 | ≥2 个自然月 | 上线后 2 个月 | snapshots 行数 |
| 体验指标 | 单次录入时长（打开页面→提交成功） | - | ≤ 30 秒 | 每次走查 | 人工计时 |

### 2.4 目标用户与角色分层

## 4. 用户故事与验收标准

### 4.1 核心用户故事

- US-E-1（打卡）：作为唯一用户，我希望每月只花 30 秒录入一次各账户余额，以便追踪方案执行并获得继续坚持的动力。
- US-E-2（偏离感知）：作为唯一用户，我希望某个月花钱明显跑偏时得到温和提示（而不是指责），以便及时纠正而不产生弃用情绪。
- US-E-3（距离感）：作为唯一用户，我希望看到「还差几个月攒满应急金、已坚持几个月」这样的具象进度，以便知道还要坚持多久。
- US-E-4（弹性）：作为唯一用户，我希望某月忘记打卡或情况特殊时不被惩罚，以便追踪习惯不因完美主义而中断。
- US-E-5（数据主权）：作为唯一用户，我希望随时把快照与方案导出为 CSV，以便数据归我、可自行分析。

### 4.2 验收标准（Given-When-Then）

**录入与覆盖**

- **AC-1（正常）**：Given 已登录且存在 active 方案（四账户），When 在 P05 录入 4 个桶余额并提交，Then 当月快照落库，P05 显示成功确认与更新后的距离感进度，`snapshot_submit` 埋点可查。
- **AC-2（异常）**：Given 录入过程中网络中断，When 提交失败，Then 展示错误提示且**已输入的数字保留在表单中**，恢复后重试成功（数据不能丢）。
- **AC-3（边界·覆盖）**：Given 当月已有快照，When 修改数字再次提交，Then 弹出覆盖确认，确认后当月记录被更新（仍每月一行），`updated_at` 变化，历史列表不出现重复月份。

**偏离提醒**

- **AC-4（正常）**：Given 存在前一条非特殊快照且同名桶前值 > 0，When 本月录入后某桶环比偏离 ≥ 阈值（默认 20%），Then P05 显示温和提示条（区分上涨/下降方向，含文案变体），不阻断任何操作。
- **AC-5（边界·特殊）**：Given 本月录入时勾选「本月特殊」，When 提交，Then 本快照不显示偏离提示，且后续月份的偏离基准跳过本条、落在更早的非特殊快照上。
- **AC-6（边界·首条）**：Given 历史无任何非特殊快照（首条录入，或历史全部为特殊），When 提交，Then 不显示偏离（无基准），显示「已坚持 1 个月」。

**距离感进度**

- **AC-7（正常）**：Given active 方案含应急金目标与必要月支出口径，且最新快照备用桶余额低于目标，When 打开 P05，Then 显示「还差 X 个月攒满应急金」（X = 缺口 ÷ 必要月支出，保留 1 位小数）与「已坚持 N 个月」。
- **AC-8（边界·达标）**：Given 最新快照备用桶余额 ≥ 应急目标，When 打开 P05，Then 显示达标态（CONTEXT「达标」语义：规则桶月转入为 0 的既定结论），缺口月数为 0。

**跳过月与删除**

- **AC-9（边界·跳过月）**：Given 3 月未录入任何数据，When 4 月录入，Then 3 月在系统中无记录；「已坚持月数」只累计有快照的月份、不因断月清零；4 月偏离以最近一条非特殊快照（2 月）为基准。
- **AC-10（异常恢复·删除）**：Given 当月快照已录但录错，When 删除当月快照并二次确认，Then 记录移除、该月回到「跳过月」语义；非最新月份不提供删除入口。

**方案版本关系**

- **AC-11（边界·换版本）**：Given 重新生成方案产生新版本且桶结构变化（含切换 L1 模式），When 录入新方案下首条快照，Then 快照关联新版本；距离感进度照常展示；偏离因桶 id 不连续而不提示，待下一条同结构快照恢复比对。

**导出**

- **AC-12（正常）**：Given 已有 ≥1 条快照，When 点击「导出快照 CSV」，Then 下载 UTF-8（带 BOM）CSV，行数 = 快照数 × 桶数（长表），Excel 打开中文不乱码、无公式注入执行。
- **AC-13（正常）**：Given 存在 active 方案，When 点击「导出方案 CSV」，Then 下载当前 active 版本的方案与各桶明细 CSV。
- **AC-14（边界·空）**：Given 快照为 0 条，When 查看 P05，Then 导出按钮置灰并以 EMPTY 文案说明（§8.4）。

**页面与安全**

- **AC-15（异常·会话）**：Given 无效会话访问 `/tracking`，Then 服务端 401，前端跳 `/login?from=/tracking`，登录后回跳 P05。
- **AC-16（异常·降级）**：Given 外部 PG 不可达，When 打开 P05，Then 展示错误态与重试入口（沿用 A 期 `/health db=error` 同源的降级链），不出现白屏。

**场景覆盖自查**：正常（AC-1/4/7/12/13）、异常（AC-2/10/15/16）、边界（AC-3/5/6/8/9/11/14）——三类齐备。

## 6. 业务规则

> 编号承接 B 期 prd-v1.md（RULE-001 ～ RULE-020），自 RULE-021 起。

- RULE-021：一条快照 = 某自然月 × 当前 active 方案的**全部桶**余额；全桶必填，缺桶不允许提交。
- RULE-022：金额单位为元、最多两位小数；允许 0 与负数（透支是真实状态）；单值绝对值 < ¥100 亿。提交前页面展示等宽千分位预览。
- RULE-023：跳过月 = 该自然月无快照记录；不产生任何提示或惩罚，不影响已坚持月数的累计值。
- RULE-024：「本月特殊」是快照上的标记；带标记的快照不触发偏离提示，也不作为任何后续环比的基准。
- RULE-025：偏离判定——基准 = 该快照之前最近一条非特殊快照；仅对两侧**同名桶**逐一比对；前值 > 0 时按百分比 |现值 − 前值| ÷ 前值 ≥ 阈值判定偏离，前值 ≤ 0 的桶不参与（从 0 起步与透支回正不按百分比误报）；阈值默认 20%，经环境变量可调（规则可调不改引擎，同 RISK-B-3 立场）。
- RULE-026：缺口月数 =（应急目标 − 最新快照备用桶余额）÷ 必要月支出，向上保留 1 位小数；应急目标与必要月支出口径**完全复用** B 期引擎结果（`plan_buckets.target_amount_cents` 与模式声明的必要桶），本期零新口径。余额 ≥ 目标即「达标」，缺口月数为 0。
- RULE-027：已坚持月数 = 有快照记录的自然月累计数（跨断月累计，不要求连续）。
- RULE-028：快照永久关联**提交时**的方案版本；历史快照不可变（仅当月允许覆盖与删除）；距离感进度始终 = 最新快照 × 当前 active 方案；偏离仅在相邻两条快照的**同名桶**之间计算，桶结构变化后首条快照不提示偏离。
- RULE-029：删除仅允许作用于**最新月**快照，需二次确认；删除后该月回到跳过月语义。
- RULE-030：导出——快照 CSV 为长表（每行 = 月 × 桶：月份 / 方案版本 / 桶 id / 桶名 / 余额 / 特殊标记），UTF-8 带 BOM，文件名含导出日期；方案 CSV = active 版本 + 各桶明细；导出内容不含任何产品名（RULE-017 继承）。
- RULE-031：免责声明沿 RULE-020 模式：P05 站点页脚一行简述 + 完整声明展开。

自检：以上每条均可回答「是/否」。

### 8.2 核心流程

```
正常路径（月度打卡）：
1. P01 追踪卡显示「本月还没打卡」→ 点「去打卡」进 P05
2. P05 顶部录入卡显示各桶名 + 空输入框（键盘为数字）
3. 逐桶输入余额 → 实时等宽千分位预览 →（可选）勾选「本月特殊」
4. 提交 → 成功确认条 + 距离感进度刷新 +（若触发）偏离提示条
5. 底部历史列表新增当月行

异常路径：
- 提交失败（网络/服务） → 错误条 + 输入保留 → 重试
- 会话过期 → 401 → 登录页（from 回跳）
- 库不可达 → 错误态 + 重试（不白屏）
- 无 active 方案 → 空态引导去问卷
```

## 9. 非功能需求（NFR）

### 9.1 性能

| 指标 | 基线（遵循 arch） | 本需求特定要求 | 验收方式 |
|------|-----------------|--------------|---------|
| P05 首屏 | 遵循基线（≤2s dev 局域级） | - | 走查 |
| 快照提交响应 | 遵循基线 | ≤ 500ms（单用户单行 upsert） | 走查/网络面板 |
| 偏离与进度计算 | 遵循基线 | ≤ 50ms（快照 ≤120 条时服务端纯函数） | 单测计时 |
| 单次录入总时长 | - | ≤ 30 秒（4 数字 + 提交） | 人工计时（§2.3） |

### 9.2 兼容性

Chrome / Edge 最新两个大版本（桌面）；Android Chrome / iOS Safari 现行版本（移动）——与既有四页一致，不额外放宽或收紧。

### 9.3 可用性与体验

- 无障碍：键盘可完成录入全流程；焦点可见；对比度沿 GitHub 契约（design-e T1 校验）；进度条同时以文本「还差 X 个月」承载（不只靠图形）
- 数据安全性感知：覆盖与删除均二次确认；本月特殊 = 无指责文案
- 离线能力：无（错误态 + 输入保留即为降级方案）
- 中断恢复：ERR-E-01 输入保留；跨页面/跨会话不留草稿（已知取舍，§8.4 ERR-E-02）

### 9.4 安全

| 维度 | 要求 |
|------|------|
| 输入校验 | 金额范围与两位小数、月份格式（YYYY-MM、不可为未来月）、桶集合与 active 方案一致（多桶/少桶/未知桶 422）；前后端同校验 |
| 越权防护 | 新端点全部落入既有 JWT 中间件（无白名单变更）；查询恒带 user_id |
| 敏感信息展示 | 余额仅登录后可见；导出文件含财务数字，文件名不含敏感词 |
| 凭证管理 | 无新增凭证；偏离阈值走 `.env`（键名进 `.env.example`） |

### 9.5 埋点与用户行为分析

金额、桶余额**永不入埋点与日志**（B 期 §8 立场继承）。

## 11. 数据合规与隐私

| 维度 | 是否涉及 | 说明 | 处理方式 |
|------|---------|------|---------|
| 个人信息收集 | 是 | 新增收集：各桶账户余额（财务数据） | 最小化：仅桶余额，不采账号/卡号；全桶必填但无身份字段 |
| 账号与认证数据 | 是 | 沿用 B 期（argon2 + JWT） | 加密存储，禁止明文；本期零变更 |
| 敏感内容（财务/健康/证件等） | **是** | 快照余额属财务敏感数据 | 鉴权后访问；不外传；日志/埋点脱敏；备份沿用 `backup.sh` + `restore-drill`（抽验扩 snapshots 表）；传输加密缺口 = RISK-E-1，已知接受（对外前必须解决） |
| 本地存储 | 否 | 无新增 localStorage 键 | -（仅既有 `ww-theme`） |
| 第三方数据传输 | 否 | 埋点入库不上报（ADR-B-005） | - |
| 数据留存与清理 | 是 | 快照长期留存（自用） | CSV 导出即数据带走通道；删除仅最新月（RULE-029）为纠错口 |
| 日志脱敏 | 是 | 金额/余额禁止进日志 | **必须**：tracing 只带 request_id + 路由名（B 期 §8 继承） |
| 家庭成员共用 | 否 | 单用户 | - |

**红线自查（PRD 基线 §11）**：
1. 无硬编码凭证 ✅（阈值走 `.env`，键名进 `.env.example`）
2. 无明文凭证、日志无敏感原文 ✅（§8 安全要点的实现落在 arch-e）
3. 数据隔离与留存：单用户，N/A 但已逐项说明 ✅
4. **资金/资产数据：准确性校验方式 = 全桶必填 + 范围/精度/桶集合校验（RULE-021/022）+ 覆盖可纠错（RULE-021/029）；备份策略 = B 期 backup.sh + restore-drill 延续并扩 snapshots 抽验** ✅
